# good-vibe:ai-assess — AI 활용 역량 평가

## 이 커맨드를 실행하면?

사용자가 제공한 문서, 폴더, 레포, 대화 내용, 업무 산출물을 근거로 AI 활용 역량을 평가합니다.
"AI를 많이 썼다"가 아니라 실제 산출물, 재사용 가능한 워크플로우, 검증 습관, 조직 확산 효과를 기준으로 진단합니다.

- **소요시간:** 3-10분
- **결과물:** 점수표, 레벨, 근거, 리스크, 30일 성장 액션 플랜
- **목적:** 개인 또는 팀의 AI 활용 수준을 증거 기반으로 파악하고 다음 개선 단계를 정합니다.

---

## 사용 예시

```text
good-vibe:ai-assess
good-vibe:ai-assess ./Q1_AI_활용_리뷰.md
good-vibe:ai-assess ./reports/ai-usage
good-vibe:ai-assess "이번 분기 AI 활용 사례를 평가해줘"
```

## Step 1: 평가 대상 확인

사용자 입력 인자: `$ARGUMENTS`

1. `$ARGUMENTS`가 파일 또는 폴더 경로이면 Read, Glob, Grep으로 관련 자료를 확인하세요.
2. `$ARGUMENTS`가 URL이면 접근 가능한 도구가 있을 때만 수집하고, 불가능하면 사용자에게 원문 또는 요약 자료를 요청하세요.
3. 인자가 없으면 현재 대화에 제공된 자료를 우선 사용하세요.
4. 근거가 부족하면 억지로 점수를 확정하지 말고 "임시 평가"로 표시하고 추가 질문을 제시하세요.

## Step 2: 평가 원칙

- 증거 기반으로 평가합니다. 근거가 없으면 "증거 불충분"으로 표시합니다.
- 직무 맥락을 반영합니다. 개발자, 리서처, 마케터, 운영 담당자에게 같은 기준을 기계적으로 적용하지 않습니다.
- 단순 사용량보다 업무 성과, 재사용성, 검증 체계, 조직 확산 효과를 더 높게 평가합니다.
- 산출물의 품질과 프로세스의 성숙도를 분리해서 판단합니다.
- 레벨 4 이상은 반복 가능하고 타인이 재사용 가능한 체계가 보여야 합니다.
- 자기 주장보다 외부에서 확인 가능한 증거를 우선합니다. "했다"보다 "결과물/로그/문서/커밋/공유 기록"을 더 높게 봅니다.
- 평가 대상이 개인이면 개인 역량을, 팀이면 팀 운영 체계를 평가합니다. 두 범위를 섞지 마세요.

## Step 3: 평가 루브릭

각 축은 0-4점으로 평가하고, 가중치를 적용해 100점 만점으로 환산합니다.

| 축                  | 가중치 | 0점                         | 1점                         | 2점                                 | 3점                                     | 4점                                             |
| ------------------- | ------ | --------------------------- | --------------------------- | ----------------------------------- | --------------------------------------- | ----------------------------------------------- |
| 문제 정의           | 15     | AI에게 무엇을 시킬지 불명확 | 단발 질문 중심              | 작업 목표와 제약 일부 명시          | 목표, 입력, 완료 기준을 명확히 정의     | 문제를 하위 작업과 평가 기준으로 체계화         |
| 컨텍스트 설계       | 15     | 맥락 제공 없음              | 배경 설명이 부족함          | 필요한 자료 일부 제공               | 역할, 자료, 제약, 톤을 안정적으로 제공  | 컨텍스트 템플릿과 기준을 재사용 가능하게 설계   |
| 워크플로우화        | 15     | 매번 즉흥적으로 사용        | 개인 프롬프트 일부 재사용   | 체크리스트나 템플릿 활용            | 반복 업무를 커맨드/스킬/문서로 표준화   | 팀 단위 자동화 자산으로 배포                    |
| 도구 오케스트레이션 | 15     | 단일 챗봇 사용              | 모델/도구를 부분적으로 활용 | 검색, 코드, 문서 도구를 목적별 사용 | 에이전트, CLI, MCP, 외부 도구를 조합    | 다단계 파이프라인을 안정적으로 운영             |
| 검증과 품질관리     | 15     | 결과를 그대로 수용          | 눈으로만 검토               | 테스트/팩트체크 일부 수행           | 리뷰, 테스트, 회귀 방지를 일관되게 수행 | 검증 기준이 자동화되고 실패 시 개선 루프가 있음 |
| 산출물 임팩트       | 15     | 업무 영향 확인 불가         | 개인 시간 일부 절감         | 품질 또는 속도 개선 사례 있음       | Before/After가 정량/정성 근거로 설명됨  | 조직 비용, 품질, 속도에 반복 가능한 성과        |
| 조직 확산           | 10     | 개인 사용에 머묾            | 공유가 비정기적             | 사용법 일부 문서화                  | 팀원이 따라 할 수 있는 가이드 제공      | 마켓플레이스, 온보딩, 교육까지 연결             |

## Step 4: 세부 관찰 지표

각 축은 아래 하위 지표를 보고 판단합니다. 모든 하위 지표가 있어야 4점인 것은 아니지만, 4점은 최소 3개 이상의 강한 증거가 있어야 합니다.

### 1. 문제 정의

- 업무 목표를 AI가 수행 가능한 작업 단위로 나눴는가
- 입력, 출력, 완료 기준, 제약 조건을 명확히 정의했는가
- 모호한 문제를 질문, 가설, 검증 기준으로 바꿨는가
- 실패 조건과 범위 밖 작업을 명시했는가

### 2. 컨텍스트 설계

- 역할, 배경, 목적, 대상 독자, 톤, 금지사항을 제공했는가
- 원본 자료, 기존 산출물, 참고 기준을 함께 제공했는가
- 프롬프트나 지시문이 재사용 가능한 구조인가
- AI가 오해할 수 있는 용어와 조직 맥락을 정의했는가

### 3. 워크플로우화

- 반복 업무를 체크리스트, 템플릿, 커맨드, 스킬, 스크립트로 만들었는가
- 시작 조건, 단계, 완료 조건, 예외 처리가 있는가
- 사람이 매번 설명하지 않아도 같은 품질로 실행되는가
- 업무 결과가 다음 작업으로 자연스럽게 이어지는가

### 4. 도구 오케스트레이션

- 하나의 모델에만 의존하지 않고 목적별 도구를 선택했는가
- 검색, 코드 실행, 문서 분석, 에이전트, CLI, MCP, 외부 SaaS를 적절히 조합했는가
- 병렬화, 역할 분담, 단계별 검토를 설계했는가
- 도구 선택 이유와 한계를 이해하고 있는가

### 5. 검증과 품질관리

- AI 결과를 테스트, 리뷰, 팩트체크, 재현 실행으로 검증했는가
- 품질 기준과 실패 기준이 사전에 정의되어 있는가
- 오류 발견 시 수정 루프가 기록되어 있는가
- 보안, 개인정보, 저작권, 환각 리스크를 점검했는가

### 6. 산출물 임팩트

- Before/After가 시간, 비용, 품질, 처리량, 오류율 중 하나 이상으로 설명되는가
- 결과물이 실제 업무 또는 의사결정에 사용되었는가
- 1회성 데모가 아니라 반복 가능한 성과인가
- 비전문가도 이해할 수 있게 효과가 설명되는가

### 7. 조직 확산

- 팀원이 따라 할 수 있는 설치/사용/운영 문서가 있는가
- 커맨드, 스킬, 템플릿, 마켓플레이스 등 배포 가능한 형태인가
- 온보딩, 교육, 공유 세션, 피드백 수집이 있었는가
- 개인 노하우가 조직 표준으로 전환되었는가

## Step 5: 증거 등급

점수 산정 시 각 근거에 증거 등급을 붙입니다.

| 등급 | 기준                               | 예시                                                  | 점수 반영                               |
| ---- | ---------------------------------- | ----------------------------------------------------- | --------------------------------------- |
| E0   | 주장만 있고 확인 자료 없음         | "AI로 많이 자동화했다"                                | 참고만 하고 고득점 근거로 사용하지 않음 |
| E1   | 산출물은 있으나 과정 확인이 어려움 | 최종 문서, 캡처, 요약본                               | 1-2점 근거                              |
| E2   | 과정과 결과가 함께 확인됨          | 커밋, PR, 작업 로그, 테스트 결과, 프롬프트 기록       | 2-3점 근거                              |
| E3   | 재사용과 검증까지 확인됨           | 커맨드/스킬/템플릿, 배포 기록, 사용 가이드, 팀 피드백 | 3-4점 근거                              |

판정 신뢰도는 아래 기준으로 정합니다.

| 신뢰도 | 기준                                                   |
| ------ | ------------------------------------------------------ |
| 높음   | E2 이상 근거가 5개 이상이고, 5개 이상의 평가 축을 커버 |
| 중간   | E1-E2 근거가 혼재하고, 3-4개 평가 축을 커버            |
| 낮음   | 자기 보고 중심이거나 2개 이하 평가 축만 확인 가능      |

## Step 6: 점수 캡과 감점 규칙

아래 조건이 있으면 해당 축 또는 총점에 상한을 적용합니다.

| 조건                                                 | 적용                            |
| ---------------------------------------------------- | ------------------------------- |
| 결과물은 있으나 검증 기록이 없음                     | 검증과 품질관리 최대 2점        |
| 개인 자동화이나 설치/사용 문서가 없음                | 조직 확산 최대 2점              |
| 정량/정성 Before-After 근거가 없음                   | 산출물 임팩트 최대 3점          |
| 프롬프트만 있고 반복 실행 구조가 없음                | 워크플로우화 최대 2점           |
| 민감정보, 저작권, 보안 리스크를 무시한 흔적이 있음   | 총점에서 5-15점 감점            |
| AI 산출물을 본인 검토 없이 그대로 제출한 정황이 있음 | 검증과 품질관리 최대 1점        |
| 자료가 자기 보고뿐임                                 | 총점 70점 초과 금지             |
| 평가 근거가 3개 미만임                               | 최종 판정 대신 임시 평가로 표시 |

## Step 7: 직무별 보정 기준

기본 7축은 동일하게 적용하되, 직무별로 특히 중요한 증거를 다르게 봅니다.

| 직무/역할         | 특히 높게 보는 증거                                                  | 주의할 점                           |
| ----------------- | -------------------------------------------------------------------- | ----------------------------------- |
| 개발자            | 테스트, PR, 코드 리뷰, 자동화 스크립트, 재현 가능한 빌드             | 코드 생성량만으로 고평가하지 않음   |
| 리서처/애널리스트 | 출처 검증, 반대 근거 검토, 인사이트 구조화, 리서치 노트 재사용       | 요약 품질과 사실 검증을 분리 평가   |
| PM/기획자         | 요구사항 분해, 의사결정 기록, 이해관계자 커뮤니케이션, 실행 가능 PRD | 문서량보다 결정 품질을 봄           |
| 마케터/콘텐츠     | 타깃/채널별 변형, 톤 관리, 성과 지표, 리뷰 루프                      | 그럴듯한 카피만으로 고평가하지 않음 |
| 운영/오퍼레이션   | SOP, 체크리스트, 예외 처리, 반복 작업 자동화, 오류 감소              | 단발 처리보다 안정성을 봄           |
| 리더/매니저       | 팀 표준화, 온보딩, 가이드 배포, 성과 측정, 거버넌스                  | 본인 활용보다 조직 확산을 더 봄     |

## Step 8: 레벨 판정

| 점수   | 레벨                  | 정의                                        |
| ------ | --------------------- | ------------------------------------------- |
| 0-39   | L1 AI 사용자          | 단발 질의와 보조 작업 중심                  |
| 40-54  | L2 작업 가속자        | 개인 업무 속도 개선이 보임                  |
| 55-69  | L3 워크플로우 빌더    | 반복 업무를 절차화하고 품질 기준을 적용     |
| 70-84  | L4 AI Native Operator | 복합 도구를 조합해 안정적 산출 체계를 운영  |
| 85-100 | L5 조직 멀티플라이어  | 팀 단위 재사용 자산과 성과 측정 체계를 확산 |

레벨 판정 시 총점뿐 아니라 필수 조건도 확인합니다.

| 레벨    | 필수 조건                                                           |
| ------- | ------------------------------------------------------------------- |
| L3 이상 | 워크플로우화 또는 검증과 품질관리 중 하나가 3점 이상                |
| L4 이상 | 도구 오케스트레이션, 검증과 품질관리, 산출물 임팩트가 모두 3점 이상 |
| L5      | 조직 확산 4점, 산출물 임팩트 4점, E3 근거 2개 이상                  |

필수 조건을 만족하지 못하면 총점이 높아도 한 단계 낮춰 판정합니다.

## Step 9: 출력 포맷

아래 형식으로 한국어 리포트를 작성하세요.

```markdown
# AI 활용 역량 평가

## 요약

- 평가 대상:
- 직무/맥락:
- 종합 점수: NN/100
- 레벨: Lx - [레벨명]
- 판정 신뢰도: 높음/중간/낮음

## 근거 자료

| 근거 | 증거 등급 | 확인 내용 | 평가에 반영한 축 |
| ---- | --------- | --------- | ---------------- |

## 점수표

| 평가 축 | 점수(0-4) | 가중 환산 | 근거 | 감점 이유 |
| ------- | --------- | --------- | ---- | --------- |

## 판정 제한

- 적용된 캡/감점:
- 레벨 하향 여부:

## 강점

1. ...
2. ...
3. ...

## 리스크

1. ...
2. ...
3. ...

## 30일 액션 플랜

| 기간  | 목표 | 실행 과제 | 완료 기준 |
| ----- | ---- | --------- | --------- |
| 1주차 | ...  | ...       | ...       |
| 2주차 | ...  | ...       | ...       |
| 3주차 | ...  | ...       | ...       |
| 4주차 | ...  | ...       | ...       |

## 추가 확인 질문

1. ...
2. ...
3. ...
```

## Step 10: 채점 계산

- 각 축의 가중 환산점 = `(축 점수 / 4) * 가중치`
- 총점 = 모든 가중 환산점 합계
- 소수점은 반올림합니다.

## Step 11: 제한
