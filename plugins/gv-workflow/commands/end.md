# Repo Tidy — 저장소 정리 자동화

끝, PR 정리, 이슈 정리, 브랜치 정리, PR 머지, 이슈 리뷰, PR 리뷰하고 머지, 이슈랑 PR 확인

현재 Git 저장소의 이슈, PR, 브랜치를 점검하고 정리합니다.

## Usage

`/gv-workflow:end` — 전체 점검 + 정리
`/gv-workflow:end review` — 점검만 (변경 없음)

## Action

### Phase 1: 현황 수집 (병렬)

다음을 **병렬로** 실행하여 현황을 파악합니다:

```bash
# 1. 열린 PR 목록 + 상태
gh pr list --state open --json number,title,headRefName,mergeable,reviewDecision,statusCheckRollup

# 2. 열린 이슈 목록
gh issue list --state open --json number,title,labels,createdAt

# 3. 원격 브랜치 목록
git branch -r --no-color

# 4. 최근 머지된 PR (브랜치 정리 참고)
gh pr list --state merged --limit 20 --json number,headRefName,mergedAt
```

### Phase 2: 분석 + 리뷰 보고

수집된 데이터를 테이블로 정리하여 사용자에게 보고합니다:

**PR별 판정 기준:**

| 조건                                                        | 판정                      |
| ----------------------------------------------------------- | ------------------------- |
| CI 전부 pass + APPROVED + MERGEABLE                         | **머지 가능**             |
| CI pass + APPROVED + 안전 경로만 변경 (docs, guides, tests) | **자동 머지 권장**        |
| CI fail 또는 CHANGES_REQUESTED                              | **수정 필요** — 이유 명시 |
| 2주 이상 방치 + 활동 없음                                   | **닫기 검토**             |

**이슈별 판정 기준:**

| 조건                                             | 판정                                |
| ------------------------------------------------ | ----------------------------------- |
| 열린 PR에서 `closes #N`으로 연결됨               | **PR에서 해결 예정**                |
| 머지된 PR에서 해결됐지만 닫히지 않음             | **닫기 가능**                       |
| 코드 버그 이슈 (문서가 아닌 실제 코드 수정 필요) | **직접 수정 필요** — 파일:라인 명시 |
| 2주 이상 방치                                    | **닫기 검토**                       |

**브랜치 판정:**

| 조건                         | 판정          |
| ---------------------------- | ------------- |
| PR이 머지/닫힘 완료된 브랜치 | **삭제 가능** |
| 열린 PR이 있는 브랜치        | **유지**      |
| PR 없는 고아 브랜치          | **삭제 검토** |

보고서를 사용자에게 보여주고, `review` 인자인 경우 여기서 종료합니다.

### Phase 3: 실행 (사용자 확인 후)

사용자에게 **실행 계획**을 보여주고 확인을 받은 후 진행합니다:

1. **PR 머지** — 머지 가능 판정된 PR을 `--squash --delete-branch`로 머지
2. **코드 버그 수정** — 직접 수정 가능한 이슈는 코드를 읽고 수정, 테스트 실행 후 커밋
3. **이슈 닫기** — 해결 완료된 이슈에 코멘트 추가 후 닫기
4. **브랜치 정리** — 삭제 가능 브랜치를 원격 + 로컬 모두 삭제
5. **최종 동기화** — `git pull`로 머지 결과 반영

### Phase 4: VPS 동기화 (선택)

VPS 접속 정보가 있는 경우 (메모리 또는 사용자 제공):

- SSH로 VPS 접속
- `git stash && git checkout main/master && git pull && git stash drop`
- 로컬 브랜치 정리 + `git remote prune origin`

### Phase 5: 최종 보고

정리 결과를 테이블로 요약:

```
## 정리 결과

| 항목 | 처리 |
|------|------|
| PR 머지 | #N, #N (N개) |
| 코드 수정 | #N (파일명) |
| 이슈 닫기 | #N, #N (N개) |
| 브랜치 삭제 | N개 (원격 N + 로컬 N) |
| VPS 동기화 | 완료/스킵 |

현재 상태: 열린 PR N개, 열린 이슈 N개
```

## 중요 규칙

- **머지 전 반드시 CI 통과 + 리뷰 상태 확인** — CI fail이면 절대 머지하지 않음
- **코드 수정 후 반드시 테스트 실행** — 테스트 실패 시 롤백
- **force push, reset --hard 사용 금지**
- **main/master 브랜치는 절대 삭제하지 않음**
- 코드 수정이 복잡하면 (3개 파일 이상 또는 로직 변경) 사용자에게 별도 작업 제안
- 한국어로 모든 보고서 작성
