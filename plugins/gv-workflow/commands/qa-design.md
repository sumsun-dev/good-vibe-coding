# /qa-design — 디자인 전문가 집단 QA 감사

디자인 QA, 디자인 토큰, 하드코딩 색상, UI 일관성, 반응형, 접근성 감사

디자인 토큰 일관성·컴포넌트 UI 패턴·반응형 레이아웃·접근성을 검사하는 4개 서브에이전트(D1~D4)를 병렬 실행하고 통합 리포트와 점수를 냅니다. **감사·보고만 합니다.** 사용자가 따로 요청하기 전에는 코드를 수정하지 않습니다.

## Usage

`/gv-workflow:qa-design` — 저장소 전체 감사
`/gv-workflow:qa-design src/components` — 지정한 경로(파일·디렉토리)만 감사

인자(`$ARGUMENTS`)가 있으면 그 경로를 감사 범위로, 없으면 저장소 루트 전체를 범위로 잡는다. 지정한 경로가 없으면 바로 멈추고 알린다.

## Action

### 1. 탐색 (메인 에이전트가 직접, 수정 없이)

서브에이전트는 이 대화를 볼 수 없으므로, 아래 결과를 **구체적인 경로로** 정리해 모든 프롬프트에 그대로 넣는다. 항상 제외: `node_modules`, `.git`, `dist`, `build`, `out`, `.next`, `.nuxt`, `coverage`, `vendor`, 생성 파일, minified 파일.

| 항목 | 찾는 방법 |
|------|----------|
| 스택 | `package.json` 의존성, 프레임워크 설정(`next.config.*`, `vite.config.*`, `nuxt.config.*`, `svelte.config.*`, `astro.config.*`, `angular.json` 등) |
| 스타일 방식 | CSS Modules / 전역 CSS / Sass / Tailwind(`tailwind.config.*`, `@theme`) / CSS-in-JS(styled-components, emotion) / UI 라이브러리 |
| 토큰 정의 파일 | `:root` 에 `--` 변수를 선언한 파일, `*token*`·`*theme*`·`*variables*` 파일, Tailwind theme 설정, 테마 헬퍼(색상 팔레트·포맷 함수 export) |
| 컴포넌트 위치 | `components/`, `app/`, `pages/`, `src/**` 중 UI 파일(`.jsx/.tsx/.vue/.svelte/.astro/.html`)이 있는 곳 |
| 공용 래퍼 컴포넌트 | 여러 곳에서 import 되는 Card·Panel·Container·Layout·EmptyState·ErrorBoundary 류 |
| 브레이크포인트 정의 | Tailwind `screens`, Sass 변수, `@custom-media`, 상수 파일 |
| UI 언어·i18n | `i18n`/`locales`/`messages` 디렉토리, `next-intl`·`react-i18next` 등, `<html lang>` |

탐색 결과가 "UI 코드 없음"(백엔드·CLI·라이브러리 전용)이면 서브에이전트를 띄우지 말고 "해당 없음 — UI 코드를 찾지 못함"과 근거(확인한 위치)만 보고하고 끝낸다.

### 2. 서브에이전트 4개 병렬 실행

**4개를 한 메시지에서 동시에** Agent(Task) 도구 `general-purpose` 로 띄운다. 각 프롬프트 = 아래 **공통 머리말** + 해당 에이전트 블록.

#### 공통 머리말 (모든 프롬프트 맨 앞에 채워서 넣기)

```
프로젝트 루트: <절대 경로>
감사 범위: <$ARGUMENTS 또는 "저장소 전체">
제외 경로: <탐색에서 정한 목록>
탐색 결과:
- 스택: <...>
- 스타일 방식: <...>
- 토큰 정의 파일: <경로 목록 | 없음>
- 컴포넌트 위치: <경로 목록>
- 공용 래퍼 컴포넌트: <이름 + 경로 | 없음>
- 브레이크포인트 정의: <경로 + 값 | 없음>
- UI 주 언어 / i18n: <예: 한국어, i18n 없음>

## 규칙
- 읽기 전용: 파일을 절대 수정·생성하지 마세요. 감사 결과만 보고합니다.
- 모든 발견 항목에 `파일:라인` 근거를 붙이세요. 근거를 댈 수 없으면 그 항목은 빼세요.
- 체크 항목의 대상이 프로젝트에 없으면 그 항목은 "해당 없음 — <이유>"로 쓰세요. 없는 문제를 만들지 마세요.
- 같은 패턴이 많으면 대표 3~5건 + 총 건수로 묶으세요.

## 심각도
- CRITICAL: 사용자가 바로 보는 깨짐·불일치, 접근 불가
- HIGH: 일관성을 반복적으로 해치는 패턴, 공용 컴포넌트·토큰 우회
- MEDIUM: 개선 권장

## 출력 형식
## <에이전트명> 감사 결과
### <체크 항목명>
- CRITICAL|HIGH|MEDIUM: [파일:라인] 설명
(해당 없음이면 "해당 없음 — 이유")
### 요약
총 N건 (Critical: X, High: Y, Medium: Z) / 해당 없음 항목: [...]
```

#### D1-Token (디자인 토큰 일관성)

```
## 역할: 디자인 토큰 일관성 감사 전문가 (D1-Token)

### 1. 하드코딩 색상
- 감사 범위의 스타일·컴포넌트 파일에서 `#[0-9a-fA-F]{3,8}`, `rgb(`, `rgba(`, `hsl(` 검색. 토큰 정의 파일은 제외.
- Tailwind면 임의값(`bg-[#...]`, `text-[rgb(...)]`), CSS-in-JS면 템플릿/객체 스타일 안의 색상도 포함.
- 토큰과 값이 같은데 하드코딩한 것(→ 토큰으로 대체 가능)과 팔레트에 없는 색상(→ 시각 불일치)을 구분.

### 2. 테마 헬퍼·토큰 미사용
- 토큰 정의 파일·테마 헬퍼가 export 하는 것(색상 팔레트, 포맷 함수 등)을 목록화.
- 같은 역할을 하면서 헬퍼를 import 하지 않고 값을 직접 쓰는 파일(예: 차트 색상 배열 직접 정의).

### 3. 타이포·간격 하드코딩
- `font-size`, `font-weight`, `line-height`, `margin/padding/gap` 의 직접 값(px/rem) vs 토큰 사용 비율.
- Tailwind면 `text-[13px]`, `p-[7px]` 같은 임의값.

심각도 가이드: 팔레트에 없는 색상 = CRITICAL, 헬퍼 우회·반복 하드코딩 = HIGH, 타이포·간격 = MEDIUM
```

#### D2-Component (컴포넌트 UI 패턴)

```
## 역할: 컴포넌트 UI 패턴 일관성 감사 전문가 (D2-Component)

### 1. 공용 래퍼 우회
- 탐색 결과의 공용 래퍼(Card/Panel/Container 등)를 대부분이 쓰는데, 같은 종류의 UI(예: 차트 라이브러리 직접 렌더링)를 래퍼 없이 만든 컴포넌트.
- 공용 래퍼가 없으면 "해당 없음".

### 2. 빈 상태·로딩·에러 UI 누락
- 데이터를 받아 렌더링하는 컴포넌트 중 `null`/`undefined`/빈 배열, 로딩, 에러 분기가 없는 것.
- 같은 프로젝트의 다른 컴포넌트가 쓰는 빈 상태 문구·컴포넌트와 다른 방식을 쓰는 것.

### 3. UI 문구 언어·i18n 일관성
- UI 주 언어와 다른 언어로 사용자에게 보이는 문자열(예: 주 언어가 한국어인데 "No data", "Loading", "Total").
- i18n 시스템이 있으면 그것을 거치지 않은 하드코딩 문자열.
- 내부 코드값(`'7d'`, `'W'`, enum 키 등)이 라벨 매핑 없이 그대로 렌더링되는 경우.

심각도 가이드: 사용자에게 다른 언어·코드값 노출 = CRITICAL, 래퍼 우회·빈 상태 누락 = HIGH
```

#### D3-Responsive (반응형 레이아웃)

```
## 역할: 반응형 레이아웃 감사 전문가 (D3-Responsive)

### 1. 브레이크포인트 통일성
- 감사 범위의 `@media` 쿼리(및 Tailwind 반응형 접두사, CSS-in-JS 미디어쿼리) 값을 모두 수집.
- 표준 = 탐색 결과의 브레이크포인트 정의. 정의가 없으면 가장 많이 쓰인 값들을 사실상 표준으로 보고 그렇게 명시.
- 표준에서 벗어난 값과 사용 위치.

### 2. Grid/Flex 레이아웃 문제
- 미디어쿼리에서 `grid-template-columns` 컬럼 수를 줄였는데 자식의 `grid-column: span N` 이 그대로라 넘치는 경우.
- 고정 컬럼 수·고정 너비로 좁은 화면에서 깨질 패턴.

### 3. Overflow 위험
- 넓은 `<table>` 을 `overflow-x: auto` 컨테이너 없이 사용.
- `white-space: nowrap` 에 말줄임·스크롤 처리 없음.
- 모바일 폭(~375px)을 넘는 고정 `width`/`min-width`.

### 4. 미디어쿼리 전략 일관성
- `min-width`(모바일 우선)와 `max-width`(데스크톱 우선) 혼용, 특히 한 파일 안에서의 혼용.

출력에 브레이크포인트 현황 표를 포함:
| 브레이크포인트 | 사용 횟수 | 파일 수 | 표준 여부 |

심각도 가이드: 확실한 레이아웃 깨짐(span 불일치 등) = CRITICAL, 비표준 브레이크포인트 = HIGH, overflow 위험·전략 혼용 = MEDIUM
```

#### D4-A11y (접근성 + 시각 계층)

```
## 역할: 접근성 및 시각 계층 감사 전문가 (D4-A11y)

### 1. 이미지 대체 텍스트
- `<img`, 프레임워크 이미지 컴포넌트(`Image` 등)에서 `alt` 누락.
- 의미 있는 이미지에 `alt=""` 사용.

### 2. 외부 링크 보안 속성
- `target="_blank"` 인데 `rel="noopener noreferrer"` 없는 `<a>` 및 프레임워크 Link 컴포넌트.

### 3. ARIA·시맨틱
- 텍스트 없이 아이콘/SVG만 있는 버튼·링크에 `aria-label` 누락.
- `div`/`span` 에 `onClick` 만 있고 `role`·`tabIndex`·키보드 핸들러가 없는 경우.
- 라벨 없는 `input`/`select`.

### 4. 색상 대비
- 글자색과 배경색을 둘 다 확인할 수 있을 때 WCAG AA(본문 4.5:1, 큰 글자 3:1) 미달. 토큰이면 토큰 정의 파일에서 값을 찾아 계산하고, 계산한 비율을 적으세요. 값을 확정할 수 없으면 보고하지 마세요.
- `opacity` 0.5 이하로 표시되는 텍스트.

### 5. 포커스 관리
- `outline: none` / `outline: 0` 에 대체 `:focus-visible` 스타일이 없는 경우.
- 양수 `tabindex` 사용.

심각도 가이드: alt 누락·키보드 접근 불가 = CRITICAL, ARIA 누락·포커스 제거·보안 속성 누락 = HIGH, 대비·개선 권장 = MEDIUM
```

### 3. 검증 및 통합 리포트

서브에이전트 보고를 그대로 믿지 않는다. **모든 CRITICAL 과 HIGH 중 표본**은 메인 에이전트가 해당 `파일:라인`을 직접 열어 확인하고, 근거가 맞지 않으면 빼거나 심각도를 낮춘다. 영역 간 중복은 하나로 합친다.

```
# 디자인 QA 감사 리포트

- 범위: <경로 | 저장소 전체>
- 스택: <요약>

## 요약
| 영역 | Critical | High | Medium | 총계 |
|------|----------|------|--------|------|
| D1-Token | X | Y | Z | N |
| D2-Component | X | Y | Z | N |
| D3-Responsive | X | Y | Z | N |
| D4-A11y | X | Y | Z | N |
| **합계** | X | Y | Z | N |

해당 없음: <영역/항목 — 이유>

## 점수: NN / 100 — 판정: PASS | 조건부 PASS | FAIL

## Critical 이슈 (즉시 수정 필요)
1. [영역] [파일:라인] 문제 — 수정 방향

## High 이슈
## Medium 이슈
```

**점수** = `100 − (Critical×10 + High×3 + Medium×1)`, 최소 0. 영역 전체가 해당 없음이면 그 영역은 계산에서 빼고 리포트에 명시한다.
**판정**: Critical 1건 이상 → FAIL / Critical 0 + High 4건 이상 → 조건부 PASS / 그 외 → PASS.

리포트 뒤에는 "수정할까요? (전체 / Critical만 / 번호 지정)" 한 줄만 묻고 멈춘다.

## 중요 규칙

1. **보고 전용**: 이 커맨드 안에서는 어떤 파일도 수정하지 않는다. 수정은 사용자가 리포트를 보고 요청할 때만.
2. **병렬 실행**: 4개 서브에이전트를 한 메시지에서 동시에 띄운다.
3. **경로 명시**: 서브에이전트 프롬프트에 탐색한 실제 경로를 넣는다. "프로젝트의 테마 파일" 같은 모호한 지시 금지.
4. **증거 기반**: 모든 이슈에 `파일:라인`. 근거 없는 항목은 버린다.
5. **해당 없음 허용**: 대상이 없으면 "해당 없음"으로 보고하고, 억지로 이슈를 만들지 않는다.
6. **반복 실행 가능**: 수정 후 다시 실행해 해소 여부를 확인한다.
