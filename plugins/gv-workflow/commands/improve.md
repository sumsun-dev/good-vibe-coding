# Improve — 작업 회고로 AI 작업 환경 개선

개선, 회고, 노하우 정리, 오류 재발 방지, 스킬 개선, 훅 추가, 세팅 개선

이 대화에서 생긴 오류·교정·반복 작업을 찾아, 다음 세션의 Claude 가 같은 실수를 안 하고 더 빨리 일하도록 메모리·CLAUDE.md·커맨드·스킬·훅을 고칩니다. **제안 → 사용자 승인 → 적용** 순서. 승인 없이 설정을 바꾸지 않는다.

## Usage

`/gv-workflow:improve` — 이 대화를 회고해 개선안 제안 후, 승인한 것만 적용
`/gv-workflow:improve review` — 제안만 (변경 없음)
`/gv-workflow:improve week` — 최근 7일 `~/daily-logs/**` 도 함께 보고 반복 패턴 위주로 제안
`/gv-workflow:improve explore` — 위 신호 중 상위 문제에 대해 외부 스킬·플러그인·MCP·오픈소스·서비스를 찾아 도입안 제안 (`week` 와 함께 써도 됨)

## Action

### 1. 신호 찾기 (대화 기록이 출처)

다음을 빠짐없이 훑는다. 각 항목은 대화 속 근거(무슨 일이 있었는지 한 줄)를 붙인다.

| 신호                                        | 예                                                       |
| ------------------------------------------- | -------------------------------------------------------- |
| 오류 → 원인 → 해결                          | 빌드 `useContext null` ← 셸 `NODE_ENV=development`       |
| 사용자 교정·불만                            | "그거 말고", "왜 또", 같은 요청 반복                     |
| 처음에 틀렸던 가정                          | 없는 파일·옵션을 있다고 함, 검증 없이 완료 선언          |
| 손으로 반복한 절차                          | 매번 같은 3단계 이상 명령 조합                           |
| 권한·도구에 막힌 것                         | 분류기 거부, 비대화형 입력 실패(`!` + 프롬프트)          |
| 사용자가 직접 해야 했던 것                  | 로그인, 비밀값 입력 — 안내 문구를 더 정확히 할 수 있는지 |
| 기존 스킬·커맨드·CLAUDE.md 가 틀렸거나 낡음 | 문서와 실제 동작 불일치                                  |

`week` 모드: `~/daily-logs/*/` 최근 7일 파일의 "막혔던 것"·"다음에 할 일" 에서 **2번 이상 나온 것**을 우선.

### 2. 어디에 고칠지 정하기 (학습 하나 = 위치 하나)

| 성격                                             | 위치                                                                 |
| ------------------------------------------------ | -------------------------------------------------------------------- |
| 이 저장소에서만 맞는 사실·명령·함정              | 그 저장소 `CLAUDE.md`                                                |
| 어느 프로젝트에서나 통하는 일하는 방식·환경 함정 | `~/.claude/rules/<주제>.md` (어느 폴더에서 열어도 읽힘)              |
| 이 사용자·이 작업 폴더에서만 맞는 선호·사실      | 자동 메모리 (세션에 안내된 memory 디렉터리, `MEMORY.md` 포인터 추가) |
| 3단계 이상, 앞으로도 반복될 절차                 | 새 커맨드 `~/.claude/commands/<name>.md` 또는 기존 커맨드 수정       |
| 매번 기계적으로 막거나 경고해야 할 것            | 훅 (`update-config` 스킬로 settings.json 수정)                       |
| 기존 커맨드·스킬의 오류                          | 그 파일 직접 수정                                                    |

규칙:

- 먼저 기존 메모리·CLAUDE.md·커맨드를 grep 해 **이미 있으면 갱신**, 새로 만들지 않는다
- 한 번뿐인 일, 이 대화에서만 의미 있는 것, git 기록에 이미 남는 것은 제외
- 훅은 가장 비싼 선택: 실패하면 모든 세션이 막힌다. 메모리·문서로 충분하면 훅을 만들지 않는다
- **안전장치를 약하게 만드는 제안 금지**: 분류기 거부(머지·배포·강제 푸시·삭제)를 자동 허용하는 권한 규칙은 만들지 않는다. 필요하면 "사용자가 직접 결정할 것" 으로만 적는다

### 2.5 외부 탐색 (`explore` 모드만)

목적은 둘러보기가 아니라 **1단계에서 찾은 문제를 남이 이미 더 잘 풀었는지** 확인하는 것.

1. 1단계 신호 중 비용이 큰 문제 최대 3개를 고른다 (반복됐거나 시간을 많이 쓴 것)
2. 문제마다 찾는다 (WebSearch 병렬):
   - Claude Code 공식 기능·설정 (claude-code-guide 에이전트로 먼저 확인 — 이미 내장일 수 있음)
   - Claude Code 플러그인·스킬·MCP 서버 (공식 마켓플레이스, Anthropic/주요 조직 GitHub)
   - 오픈소스 라이브러리·CLI, 외부 서비스
3. 후보마다 평가:

   | 기준      | 확인                                                               |
   | --------- | ------------------------------------------------------------------ |
   | 문제 적합 | 우리 문제를 실제로 푸는가, 지금 방식보다 무엇이 나은가             |
   | 신뢰      | 관리 주체, 최근 커밋·릴리스, 스타·이슈 대응, 라이선스              |
   | 보안      | 요구 권한·토큰, 코드가 어디서 실행되는지, 데이터가 외부로 나가는지 |
   | 비용      | 무료 한도, 유료 전환 조건, 설치·유지 부담                          |
   | 대안      | 이미 설치된 것(플러그인·스킬·의존성)으로 되는지 — 되면 그걸 우선   |

4. 결론은 **도입 / 보류 / 불필요** 중 하나. 이미 있는 것으로 충분하면 "불필요" 가 정답
5. 설치·가입·플러그인 추가·외부 서비스 연결은 **제안만** 한다. 실행은 사용자 승인 후, 신뢰할 수 있는 출처에서만. 처음 보는 저장소의 스크립트를 바로 실행하지 않는다

보고 형식:

```
## 찾아본 도구

| 문제 | 후보 | 결론 | 이유 (적합·신뢰·보안·비용) | 링크 |
|------|------|------|---------------------------|------|
```

### 3. 제안 보고 (한국어)

```
## 개선 제안

| # | 무엇을 | 어디에 | 근거 (오늘 있었던 일) | 효과 |
|---|--------|--------|----------------------|------|
| 1 | ... | memory/feedback | ... | 다음엔 ... 안 함 |

제외한 것: (한 줄씩, 왜 뺐는지)
```

각 제안은 실제로 넣을 문구나 diff 를 짧게 함께 보여준다. `review` 모드는 여기서 끝.

### 4. 적용 (승인한 번호만)

- AskUserQuestion(multiSelect)으로 적용할 번호를 받는다
- 메모리: 세션에 안내된 메모리 규칙(frontmatter, 한 파일 한 사실, MEMORY.md 한 줄 포인터) 그대로. 메모리는 실행한 폴더마다 따로 저장되므로, 프로젝트를 가리지 않는 교훈은 `~/.claude/rules/` 를 우선
- 훅·settings: `update-config` 스킬 사용. 적용 후 훅 명령을 한 번 직접 실행해 문법 오류가 없는지 확인
- 커맨드·스킬: 기존 파일 형식(제목, 트리거 줄, Usage, Action, 중요 규칙)을 따른다
- 저장소 `CLAUDE.md` 수정은 그 저장소의 작업 트리 변경이 되므로 사용자에게 커밋 여부를 묻는다

### 5. 기록

적용한 것을 `~/daily-logs/_general/YYYY-MM-DD.md` 의 `## 환경 개선` 섹션에 덧붙인다 (없으면 만든다):

- 무엇을 어디에 바꿨는지, 근거 한 줄

## 중요 규칙

- 한국어로 보고
- 근거 없는 제안 금지 — 이 대화(또는 daily-logs)에서 실제로 있었던 일만
- 승인 없이 적용 금지
- 안전장치 완화 금지
- 비밀값 원문 금지
- 적게, 정확하게: 효과 큰 것 5개 이내
- 외부 도구는 실제 문제가 있을 때만 찾는다. 유행한다는 이유로 도입 제안하지 않는다
- 설치·가입·외부 연결은 승인 후에만, 출처 확인 후에만
