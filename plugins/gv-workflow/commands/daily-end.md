# Daily End — 오늘 작업 정리 + 다음 할 일

하루 마무리, 오늘 한 일 정리, 작업 일지, 데일리 로그

이 대화에서 한 작업을 이해하기 쉽게 정리하고, 다음에 할 일과 함께 프로젝트별로 `~/daily-logs/<프로젝트>/YYYY-MM-DD.md` 에 저장합니다.

## Usage

`/gv-workflow:daily-end` — 오늘 작업 정리 후 저장
`/gv-workflow:daily-end <메모>` — 메모를 "다음 할 일" 에 함께 반영

## Action

### 1. 재료 모으기

- **대화 기록이 1차 출처.** 사용자가 요청한 것, 실제로 한 것, 막힌 것, 사용자가 직접 한 것(로그인·비밀값 입력·머지 등)을 구분한다
- 작업한 git 저장소마다 보조 확인 (병렬):
  ```bash
  git log --since=midnight --oneline --all
  gh pr list --state all --search "updated:>=$(date +%F)" --json number,title,state,url
  git status --short
  ```
- 확인 안 된 것은 "한 것" 에 넣지 않는다. 진행 중·결과 대기 중이면 그렇게 적는다

### 2. 정리 (한국어, 비개발자도 읽히게)

- 작업 묶음 단위로 쓴다 (커밋 단위 X). 각 묶음은 **무엇을 왜 했고, 이제 뭐가 달라졌는지** 1~3줄
- 전문 용어는 처음 나올 때 한 번 풀어 쓴다 (예: "R2 — Cloudflare 파일 저장소")
- 막혔다가 해결한 문제는 원인 한 줄 + 해결 한 줄
- 비밀값(비밀번호·토큰·키)은 **이름만** 적고 값은 절대 적지 않는다

### 3. 파일 쓰기

경로: `~/daily-logs/<프로젝트>/YYYY-MM-DD.md` (폴더 없으면 생성)

- **프로젝트 = 작업한 git 저장소 이름** (`basename $(git rev-parse --show-toplevel)`, 예: `my-site`)
- 여러 저장소를 작업했으면 **저장소마다 파일을 따로** 쓴다. 각 파일에는 그 저장소 작업만 넣는다
- 저장소 밖 작업(Claude 설정, 메모리, 브라우저 작업 등)은 `~/daily-logs/_general/` 에 쓴다
- 저장소 간에 이어지는 일이 있으면 "다음에 할 일" 에 상대 파일 경로를 적어 잇는다

같은 날 파일이 이미 있으면 덮어쓰지 말고 맨 아래에 `---` 후 새 세션 블록을 덧붙인다 (`## 세션 HH:MM`).

형식:

```markdown
# YYYY-MM-DD <프로젝트> 작업 일지

## 한 줄 요약

오늘의 핵심 성과 1~2문장

## 오늘 한 일

### 1. <작업 묶음 제목> (`<저장소>`)

- 무엇을/왜, 결과
- 관련: PR #N, 커밋, URL

## 막혔던 것 · 해결

- 증상 → 원인 → 해결

## 현재 상태

| 항목                       | 상태 |
| -------------------------- | ---- |
| 저장소/브랜치/열린 PR·이슈 | ...  |
| 배포                       | ...  |

## 다음에 할 일

- [ ] 구체적인 다음 행동 (누가: 나/Claude, 어디서)
- [ ] 결과 확인이 남은 것 (언제 확인할지)

## 알아두면 좋은 것

- 앞으로 반복될 방법·주의점 (명령어 포함)
```

빈 섹션은 지운다.

### 4. 보고

채팅에는 파일마다 저장 경로 + "한 줄 요약" + "다음에 할 일" 만 짧게 보여준다. 전체 내용은 파일에 있다.

"막혔던 것 · 해결" 에 항목이 있으면 마지막 줄에 `/gv-workflow:improve` 로 재발 방지책을 만들 수 있다고 한 줄 안내한다.

## 중요 규칙

- 한국어로 작성
- 추측 금지: 대화와 git 에서 확인한 것만
- 비밀값 원문 금지
- 기존 일지를 덮어쓰지 않음 (덧붙이기만)
