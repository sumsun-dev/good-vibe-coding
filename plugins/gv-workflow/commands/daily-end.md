# Daily End — 저장소 정리 + 오늘 작업 정리 + 다음 할 일

하루 마무리, 끝, 오늘 한 일 정리, 작업 일지, 데일리 로그, PR 정리, 이슈 정리, 브랜치 정리, 레포 최신화

작업한 저장소의 PR·이슈·브랜치를 점검해 정리하고 원격과 맞춘 뒤, 이 대화에서 한 작업을 다음 할 일과 함께 `~/daily-logs/<프로젝트>/YYYY-MM-DD.md` 에 저장합니다.

## Usage

`/gv-workflow:daily-end` — 저장소 점검 → (확인 후) 정리 → 일지 저장
`/gv-workflow:daily-end review` — 저장소는 점검만 하고 바꾸지 않음, 일지는 저장
`/gv-workflow:daily-end <메모>` — 메모를 "다음 할 일" 에 함께 반영

## Action

### 1. 재료 모으기 (병렬)

- **대화 기록이 1차 출처.** 사용자가 요청한 것, 실제로 한 것, 막힌 것, 사용자가 직접 한 것(로그인·비밀값 입력·머지 등)을 구분한다
- 작업한 git 저장소마다:
  ```bash
  git fetch --quiet --prune
  git status -sb | head -1          # 브랜치, 원격 대비 ahead/behind
  git status --short                # 미커밋 파일
  git log --since=midnight --oneline --all
  git log --branches --not --remotes --oneline   # 푸시 안 한 커밋
  git branch -vv --no-color         # 로컬 브랜치 + 원격 추적 상태([gone] 포함)
  gh pr list --state open --json number,title,headRefName,mergeable,reviewDecision,statusCheckRollup,updatedAt
  gh pr list --state merged --limit 20 --json number,headRefName,mergedAt
  gh pr list --state all --search "updated:>=$(date +%F)" --json number,title,state,url
  gh issue list --state open --json number,title,labels,updatedAt
  ```
- `gh` 가 없거나 인증이 안 돼 있으면 PR·이슈 단계는 건너뛰고 일지에 "gh 없음 — PR·이슈 미확인" 이라 적는다. 멈추지 않는다
- 확인 안 된 것은 "한 것" 에 넣지 않는다. 진행 중·결과 대기 중이면 그렇게 적는다

### 2. 저장소 점검 보고

판정 결과를 표로 보여준다. 해당 없는 표는 생략한다.

**동기화**

| 조건            | 판정                                             |
| --------------- | ------------------------------------------------ |
| 푸시 안 한 커밋 | **푸시 권장** — 브랜치·커밋 수 명시              |
| 원격보다 behind | **pull 필요** (미커밋 변경이 있으면 먼저 알림)   |
| 미커밋 파일     | **알림만** — 오늘 작업 것인지 무관한 것인지 구분 |

**PR**

| 조건                                                        | 판정                      |
| ----------------------------------------------------------- | ------------------------- |
| CI 전부 pass + APPROVED + MERGEABLE                         | **머지 가능**             |
| CI pass + APPROVED + 안전 경로만 변경 (docs, guides, tests) | **자동 머지 권장**        |
| CI fail 또는 CHANGES_REQUESTED                              | **수정 필요** — 이유 명시 |
| 2주 이상 활동 없음                                          | **닫기 검토**             |

**이슈**

| 조건                               | 판정                            |
| ---------------------------------- | ------------------------------- |
| 열린 PR에서 `closes #N`으로 연결됨 | **PR에서 해결 예정**            |
| 머지된 PR에서 해결됐지만 열려 있음 | **닫기 가능**                   |
| 실제 코드 수정이 필요한 버그       | **다음 할 일로** — 파일:줄 명시 |
| 2주 이상 활동 없음                 | **닫기 검토**                   |

**브랜치**

| 조건                                    | 판정          |
| --------------------------------------- | ------------- |
| PR 머지·닫힘 완료, 또는 원격이 `[gone]` | **삭제 가능** |
| 열린 PR이 있음                          | **유지**      |
| PR 없는 고아 브랜치                     | **삭제 검토** |

`review` 인자면 정리하지 않고 4단계(일지)로 간다.

### 3. 정리 실행 (사용자 확인 후)

실행 계획을 한 번에 보여주고 확인을 받은 뒤 진행한다. 사용자가 고른 것만 한다.

1. **푸시** — 푸시 안 한 커밋 (새 브랜치면 `-u`)
2. **PR 머지** — 머지 가능 판정만 `--squash --delete-branch`
3. **이슈 닫기** — 해결 근거(PR·커밋)를 코멘트로 남기고 닫기
4. **브랜치 삭제** — 삭제 가능 판정만, 원격 + 로컬
5. **동기화** — 기본 브랜치로 `git pull`, `git remote prune origin`. 미커밋 변경이 있으면 checkout 하지 않고 알린다

머지·푸시·삭제가 권한 정책에 막히면 다른 방법으로 우회하지 않는다. 남은 명령을 `! cd <저장소> && ...` 한 줄로 묶어 사용자에게 넘기고, 일지 "다음에 할 일" 에도 적는다.

### 4. 일지 정리 (한국어, 비개발자도 읽히게)

- 작업 묶음 단위로 쓴다 (커밋 단위 X). 각 묶음은 **무엇을 왜 했고, 이제 뭐가 달라졌는지** 1~3줄
- 전문 용어는 처음 나올 때 한 번 풀어 쓴다 (예: "R2 — Cloudflare 파일 저장소")
- 막혔다가 해결한 문제는 원인 한 줄 + 해결 한 줄
- "현재 상태" 는 **3단계 정리 후** 상태로 쓴다
- 비밀값(비밀번호·토큰·키)은 **이름만** 적고 값은 절대 적지 않는다

### 5. 파일 쓰기

경로: `~/daily-logs/<프로젝트>/YYYY-MM-DD.md` (폴더 없으면 생성)

- **프로젝트 = 작업한 git 저장소 이름** (`basename $(git rev-parse --show-toplevel)`, 예: `my-site`)
- 여러 저장소를 작업했으면 **저장소마다 파일을 따로** 쓴다. 각 파일에는 그 저장소 작업만 넣는다
- 저장소 밖 작업(Claude 설정, 메모리, 브라우저 작업 등)은 `~/daily-logs/_general/` 에 쓴다
- 저장소 간에 이어지는 일이 있으면 "다음에 할 일" 에 상대 파일 경로를 적어 잇는다

같은 날 파일이 이미 있으면 덮어쓰지 말고 맨 아래에 `---` 후 새 세션 블록을 덧붙인다 (`## 세션 HH:MM`).

형식:

```markdown
# YYYY-MM-DD <프로젝트> 작업 일지

## 한 줄 요약

오늘의 핵심 성과 1~2문장

## 오늘 한 일

### 1. <작업 묶음 제목> (`<저장소>`)

- 무엇을/왜, 결과
- 관련: PR #N, 커밋, URL

## 막혔던 것 · 해결

- 증상 → 원인 → 해결

## 저장소 정리

| 항목        | 처리              |
| ----------- | ----------------- |
| 푸시        | 브랜치 (커밋 N개) |
| PR 머지     | #N, #N            |
| 이슈 닫기   | #N                |
| 브랜치 삭제 | 원격 N + 로컬 N   |
| 동기화      | 완료 / 스킵(이유) |

## 현재 상태

| 항목                       | 상태 |
| -------------------------- | ---- |
| 저장소/브랜치/열린 PR·이슈 | ...  |
| 배포                       | ...  |

## 다음에 할 일

- [ ] 구체적인 다음 행동 (누가: 나/Claude, 어디서)
- [ ] 결과 확인이 남은 것 (언제 확인할지)

## 알아두면 좋은 것

- 앞으로 반복될 방법·주의점 (명령어 포함)
```

빈 섹션은 지운다.

### 6. 보고

채팅에는 저장소 정리 결과 표 + 파일마다 저장 경로 + "한 줄 요약" + "다음에 할 일" 만 짧게 보여준다. 전체 내용은 파일에 있다.

"막혔던 것 · 해결" 에 항목이 있으면 마지막 줄에 `/gv-workflow:improve` 로 재발 방지책을 만들 수 있다고 한 줄 안내한다.

## 중요 규칙

- 한국어로 작성
- 추측 금지: 대화와 git 에서 확인한 것만
- 비밀값 원문 금지
- 기존 일지를 덮어쓰지 않음 (덧붙이기만)
- 머지 전 CI 통과 + 리뷰 상태 확인 — CI fail 이면 머지하지 않음
- force push, `reset --hard`, `git add -A` 금지. main/master 는 삭제하지 않음
- 코드 수정은 하지 않는다 — 고칠 버그는 "다음에 할 일" 로 넘긴다
