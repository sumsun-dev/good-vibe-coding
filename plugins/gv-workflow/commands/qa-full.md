# /qa-full — 통합 QA 감사 오케스트레이터

전체 QA, 통합 감사, 디자인+데이터 QA, 릴리스 전 점검

디자인 전문가 집단(D1~D4)과 데이터 전문가 집단(A1~A4), 총 8개 서브에이전트를 병렬 실행해 하나의 통합 리포트·점수·수정 로드맵을 냅니다. **감사·보고만 합니다.** 사용자가 따로 요청하기 전에는 코드나 데이터를 수정하지 않습니다.

## Usage

`/gv-workflow:qa-full` — 저장소 전체 감사
`/gv-workflow:qa-full src` — 지정한 경로만 감사 (두 집단 모두 같은 범위)

한 집단만 다시 보려면 `/gv-workflow:qa-design` 또는 `/gv-workflow:qa-data` 를 쓴다.

## Action

### 1. 에이전트 정의 불러오기

8개 에이전트의 공통 머리말·체크리스트·심각도·출력 형식은 이 플러그인의 두 커맨드 파일에 있다. **둘 다 끝까지 읽고 그대로 쓴다** (요약·축약 금지):

- `${CLAUDE_PLUGIN_ROOT}/commands/qa-design.md` — D1-Token, D2-Component, D3-Responsive, D4-A11y
- `${CLAUDE_PLUGIN_ROOT}/commands/qa-data.md` — A1-Schema, A2-Eval, A3-Coverage, A4-Integrity

`${CLAUDE_PLUGIN_ROOT}` 가 치환되지 않았으면 `~/.claude/plugins` 아래에서 `**/gv-workflow/commands/qa-design.md`, `**/gv-workflow/commands/qa-data.md` 를 찾는다. 찾지 못하면 추측해서 프롬프트를 지어내지 말고 멈춰서 알린다.

### 2. 탐색 (한 번만)

두 파일의 "1. 탐색" 표를 합쳐 한 번에 수행한다(스택, 스타일·토큰, 컴포넌트, 브레이크포인트, UI 언어, 데이터 파일·그룹 구조, 스키마, 평가 로직, 오늘 날짜). 인자(`$ARGUMENTS`)가 있으면 그 경로가 범위, 없으면 저장소 전체. 지정한 경로가 없으면 멈추고 알린다.

- UI 코드가 없으면 디자인 4개는 띄우지 않고 "디자인: 해당 없음"으로 기록.
- 데이터 파일·스키마·평가 로직이 모두 없으면 데이터 4개는 띄우지 않고 "데이터: 해당 없음"으로 기록.
- 둘 다 없으면 그 사실과 근거만 보고하고 끝낸다.

### 3. 서브에이전트 병렬 실행

띄울 에이전트(최대 8개)를 **한 메시지에서 동시에** Agent(Task) 도구 `general-purpose` 로 띄운다. 각 프롬프트 = 해당 커맨드 파일의 **공통 머리말**(탐색 결과로 채움) + 해당 에이전트 블록.

프로젝트 지침(CLAUDE.md 등)이 동시 서브에이전트 수를 제한하면 그에 따라 4+4 두 배치로 나눈다. 배치 1: D1, D2, A1, A2 / 배치 2: D3, D4, A3, A4.

### 4. 검증 및 통합 리포트

서브에이전트 보고를 그대로 믿지 않는다. **모든 CRITICAL 과 HIGH 중 표본**은 근거 위치를 직접 열어 확인하고, 맞지 않으면 빼거나 심각도를 낮춘다. 디자인·데이터 간 중복(예: D2 의 빈 상태 누락과 A3 의 데이터 누락이 같은 화면)은 하나로 합치고 두 영역을 함께 표기한다.

```
# QA 전체 감사 리포트

## 실행 정보
- 실행 일시: <날짜/시간>
- 프로젝트: <저장소 이름> / 범위: <경로 | 저장소 전체>
- 스택: <요약>
- 에이전트: N개 (디자인 X + 데이터 Y), 해당 없음: <영역 — 이유>

## 요약
| 영역 | Critical | High | Medium | 총계 |
|------|----------|------|--------|------|
| D1-Token (디자인 토큰) | X | Y | Z | N |
| D2-Component (UI 패턴) | X | Y | Z | N |
| D3-Responsive (반응형) | X | Y | Z | N |
| D4-A11y (접근성) | X | Y | Z | N |
| A1-Schema (스키마) | X | Y | Z | N |
| A2-Eval (평가 로직) | X | Y | Z | N |
| A3-Coverage (커버리지) | X | Y | Z | N |
| A4-Integrity (정합성) | X | Y | Z | N |
| **디자인 소계** | X | Y | Z | N |
| **데이터 소계** | X | Y | Z | N |
| **합계** | X | Y | Z | N |

## 점수
| 집단 | 점수 | 판정 |
|------|------|------|
| 디자인 | NN / 100 | PASS / 조건부 PASS / FAIL / 해당 없음 |
| 데이터 | NN / 100 | ... |
| **종합** | NN / 100 | ... |

---

## Critical 이슈 (즉시 수정 필요)
### 데이터 Critical
1. [영역] 제목
   - 위치: [근거]
   - 문제: 무엇이 왜 잘못됐는지
   - 수정 방향: 한 줄
### 디자인 Critical
(같은 형식)

## High 이슈
### 데이터 High
### 디자인 High

## Medium 이슈
### 데이터 Medium
### 디자인 Medium

---

## 수정 로드맵 (제안)
### Phase 1: Critical (N건)
- [ ] [영역] 이슈 — 수정 방향
### Phase 2: High (N건)
### Phase 3: Medium (N건)

## 재실행 안내
수정 후 `/gv-workflow:qa-full` 로 해소 여부를 확인하세요.
한 집단만 다시 보려면 `/gv-workflow:qa-design` 또는 `/gv-workflow:qa-data`.
```

**점수**: 집단별로 `100 − (Critical×10 + High×3 + Medium×1)`, 최소 0. 해당 없음 영역은 계산에서 뺀다. 종합 점수 = 해당 없음이 아닌 집단 점수의 평균.
**판정**: Critical 1건 이상 → FAIL / Critical 0 + High 4건 이상 → 조건부 PASS / 그 외 → PASS. 종합 판정은 두 집단 중 낮은 쪽을 따른다.

리포트 뒤에는 "로드맵대로 수정할까요? (Phase 1만 / 전체 / 번호 지정)" 한 줄만 묻고 멈춘다.

## 중요 규칙

1. **보고 전용**: 이 커맨드 안에서는 어떤 파일도 수정하지 않는다. 수정은 사용자가 리포트를 보고 요청할 때만.
2. **병렬 실행**: 띄울 서브에이전트를 한 메시지에서 동시에. 프로젝트 지침이 제한할 때만 4+4 배치.
3. **같은 정의 사용**: 에이전트 프롬프트는 `qa-design.md`·`qa-data.md` 의 내용을 그대로 쓴다. 여기서 새로 지어내지 않는다.
4. **경로 명시**: 모든 프롬프트에 탐색한 실제 경로를 넣는다. 서브에이전트는 이 대화를 볼 수 없다.
5. **증거 기반**: 모든 이슈에 `파일:라인`(데이터는 `파일 → JSON 경로` 허용). 근거 없는 항목은 버린다.
6. **해당 없음 허용**: 대상이 없는 영역은 "해당 없음"으로 보고하고 점수에서 뺀다.
7. **독립 검증**: 서브에이전트 보고는 교차 확인 후에만 리포트에 싣는다.
