# landing-demo — 랜딩 제품 데모 애니메이션

랜딩의 그림 한 장 자리에 **실제 앱 화면을 옮긴 짧은 장면**을 넣는다. 보는 사람은 앱을 깔기 전에 "이렇게 물으면 이렇게 답하는구나"를 본다.
움직임 부품과 화면 규칙은 [Stageshow](https://github.com/benjitaylor/skills/tree/main/stageshow)(Benji Taylor, MIT)를 원본에서 받아 쓴다. 이 스킬은 거기에 **실제 제품과 맞추는 법, 한국어 화면, Next.js, 촬영·측정**을 더한다.

## 0. 범위 확인

| 대상                               | 판정  | 이유                                                            |
| ---------------------------------- | ----- | --------------------------------------------------------------- |
| React·Next.js 랜딩, 기능 소개 카드 | 한다  | kit 이 DOM·CSS 로 그린다                                        |
| React Native·Expo 앱 화면 자체     | 안 함 | DOM 이 없다. 앱 화면을 **그림으로 옮겨** 웹 랜딩에 넣는 건 된다 |
| 앱스토어·플레이 스크린샷           | 안 함 | 스토어는 실제 앱 화면을 요구한다. 꾸민 화면은 심사 위험         |
| 실제 서비스 화면 다듬기            | 안 함 | `kr-service-style`·`hangul-wrap` 이 맡는다                      |

장면 하나만 만든다. 기능마다 애니메이션을 붙이지 않는다(산만해진다). 나머지는 정적 카드로 둔다.

## 1. 원본 받기와 읽기

```bash
git clone --depth 1 https://github.com/benjitaylor/skills.git <scratchpad>/bt-skills
git -C <scratchpad>/bt-skills log -1 --format=%H   # 커밋을 기록해 둔다(보고·주석용)
```

읽는 순서: `stageshow/SKILL.md` → `references/framing.md`·`craft.md` 전부 → `motion.md` 의 Story·Loops·Changing text → `kit.md` 에서 쓸 부품 항목만.
`examples/` 에서 이야기가 가장 가까운 예시 하나를 골라 코드를 읽는다(AI 답변이면 `ai-chat`, 폰이면 `phone-touch`·`messages`).

## 2. 장면 설계 — 지어내지 않는다

코드 쓰기 전에 다섯 줄을 먼저 적는다: **자리(페이지의 어디, 칸 폭) / 주인공(폰·창) / 행동 / 결과(마지막 장면) / 뺄 것**.

- **화면 모양은 실제 제품 소스에서 옮긴다.** 앱 저장소의 화면 파일·테마 토큰(색·모서리·글자 크기)을 읽고 그 값을 쓴다. kit 기본 회색 화면으로 두지 않는다. 옮긴 원본 경로를 컴포넌트 첫 주석에 적어 "실제 화면이 바뀌면 함께 고친다"고 남긴다
- **내용은 검증된 것만.** 답변·숫자·출처는 제품이 실제로 낼 수 있는 것, 그리고 근거 자료(검토된 카드·공식 문서)에 있는 문장만 쓴다. 의료·금융·법률이면 특히 지어내지 않는다. 쓴 근거 파일 경로도 주석에 남긴다
- **진짜 글자는 3~7개.** 제목, 행동(입력한 질문), 결과(답·숫자), 출처 정도. 나머지는 kit `Bar`(회색 막대)
- **박자 3~5개, 10~16초.** 예: 입력 → 보내기 → 처리 중 → 결과가 흘러나옴 → 근거가 붙음
- **랜딩은 `play="once"` + `poster` 가 기본.** 한 번 재생하고 결과 장면에서 멈춘다. `poster` 는 결과가 다 보이는 장면(움직임 줄이기 설정·썸네일에서 이것만 보인다)
- 문장 끝 각주(`[1]`)·단위가 혼자 다음 줄로 떨어지면 문장을 줄인다

## 3. kit 가져오기 — 필요한 파일만

`kit/index.ts` 로 통째 가져오지 않는다. 부품마다 CSS 를 불러오므로 안 쓰는 부품의 CSS 까지 실리고, `Icon` 때문에 `lucide-react` 의존성이 생긴다.

```bash
node <이 스킬 폴더>/kit-pick.mjs <bt-skills>/stageshow/kit <대상>/components/stageshow/kit stage.tsx phone.tsx window.tsx motion/Collapse.tsx motion/Stream.tsx parts/Spinner.tsx
```

- 쓴 부품의 의존 파일(.ts·.tsx·.css)까지 따라가서 복사하고 목록을 출력한다. 원본 `LICENSE` 도 `<대상>/components/stageshow/` 에 함께 복사한다(MIT 고지)
- 같은 폴더에 `README.md` 를 두고 원본 URL·1단계에서 기록한 커밋·가져온 파일 목록·`kit-pick` 에 넘긴 부품을 적는다(나중에 원본을 갱신할 때 쓴다)
- 가져올 때는 파일을 직접 가리킨다: `import { Stage } from './stageshow/kit/stage'`
- `brands/`(다른 회사 로고, 라이선스 따로)는 쓰지 않는다

**Next.js**

| 상황         | 할 일                                                                                                       |
| ------------ | ----------------------------------------------------------------------------------------------------------- |
| 공통         | 데모 컴포넌트 첫 줄 `'use client'`. 페이지는 서버 컴포넌트로 둬도 된다                                      |
| App Router   | 부품의 `import './x.css'` 그대로 된다                                                                       |
| Pages Router | `_app` 밖의 전역 CSS 는 빌드 오류 → 부품의 CSS import 를 지우고 `kit/stageshow.css` 를 `_app` 에서 한 번    |
| 보안 헤더    | CSP 에 `unsafe-eval` 이 없으면 dev 에서만 React eval 경고가 뜬다. 운영과 무관(원래 있던 경고인지 먼저 확인) |

## 4. 배치 — 칸 폭이 곧 디자인 폭

- **무대 폭 = 놓일 칸의 실제 폭.** 데스크톱에서 축소 배율이 1 이 되게 칸을 고정한다(예: `grid-template-columns: 1fr 380px`). 휴대폰(390 화면의 358 칸)에서 0.85 아래로 줄면 `compact` 디자인을 따로 만든다
- **좁은 폭도 잰다: 360·320.** 축소 비율은 마운트 뒤에 정해지므로, 그 전에 무대가 칸을 넘지 않게 데모 루트에 `overflow: hidden` 을 준다. 320 에서 10px 아래로 떨어지면 `compact` 를 만들거나 그 폭은 한계로 보고한다
- **폰은 340px 이상**, 위에서 한 칸 띄우고 아래로 잘린다(10~40%). 폰 안 크기는 `calc(var(--ps) * N)` 로 앱과 같은 pt 값을 쓴다
- **가장 작은 글자 10px 이상**(축소 반영). 앱의 12~13pt 글자는 폰 배율에서 9px 대로 떨어지므로 14pt 로 올린다
- **무대 높이는 재서 정한다.** 시작·끝 장면에서 마지막 요소의 아래 끝을 잰다(5단계 `--track`). 끝 장면의 마지막 요소 + 한 칸(약 24px)에서 자른다. 버튼·입력칸이 잘리는 선에 걸리면 높이를 바꾼다
- **시작 장면이 비면** 앱의 실제 첫 화면 분량(소개 카드의 줄 수·줄 간격)을 막대로 채운다. 빈 띠를 없애려고 없는 요소를 지어내지 않는다
- **바탕은 페이지의 카드 언어.** 같은 모서리·옅은 브랜드 색 면. 흰 페이지에 창을 띄워 사방이 비면 실패다

## 5. 찍고 고치기

먼저 원본 검사를 시도한다: `node <bt-skills>/stageshow/scripts/film.mjs <url> --select '<루트 선택자>' --gate`. `rehearsal passed` 가 나올 때까지 고친다.
외부 스크립트이니 실행 전에 읽어 보고, 1단계에서 기록한 커밋 그대로 쓴다(그사이 `git pull` 하지 않는다).
**외부 코드 실행이 막히거나 브라우저가 없으면** 이 스킬의 `film-lite.mjs` 로 대신한다(저장소의 playwright·playwright-core 를 찾아 쓴다).

```bash
cd <대상 저장소> && node <이 스킬 폴더>/film-lite.mjs http://localhost:3000/ --select .cd \
  --widths 1280,390,360,320 --times 0,1500,2600,3300,4200,5200,6500,8000,10500 \
  --track .cd-answer,.cd-field,.cd-send --out <scratchpad>/shots
```

- 출력: 폭마다 시간별 PNG, 한 장으로 모은 `sheet-<폭>.png`, 그리고 JSON(무대 크기·축소 배율·가장 작은 글자 4개·가로 넘침·콘솔 오류·`--track` 요소의 무대 좌표 위·아래)
- 시트를 직접 열어 본다. 숫자만 보고 통과라 하지 않는다
- Next dev 의 "N Issue" 표시가 장면을 가리면 운영 빌드(`next build && next start`)로 찍는다
- 처음·끝뿐 아니라 **중간 장면**(처리 중, 흘러나오는 중)도 본다. 빈 띠는 대개 중간에 생긴다

**자주 나온 결함 (고치고 다시 찍는다)**

| 보이는 것                        | 원인                                      | 고치기                                                  |
| -------------------------------- | ----------------------------------------- | ------------------------------------------------------- |
| 작은 글자 10px 미만              | 폰 배율 × 무대 축소                       | 칸 폭 고정, 작은 글자 14pt                              |
| 시작·끝 장면 아래가 빈 크림색 띠 | 무대가 내용보다 김                        | `--track` 으로 재서 높이 조정, 실제 첫 화면 분량 채우기 |
| 본문이 흐린 회색                 | kit 기본 글자색(`--ss-text`)              | 답 문단에 제품 본문색, `.ss-stream { color: inherit }`  |
| `[1]`·단위 혼자 다음 줄          | 문장이 칸보다 살짝 김                     | 문장 줄이기                                             |
| 보낸 뒤에도 입력칸에 초점 테두리 | 상태를 하나로 묶음                        | `data-focus` 를 보내기 전에만                           |
| 결과 카드가 빈 채로 먼저 열림    | `Stream` 은 최종 높이를 먼저 잡는다(의도) | 받아들이거나 처리 중 시간을 줄여 빈 시간을 짧게         |

## 6. 마무리 확인

1. 움직임 줄이기: `film-lite.mjs --reduced` 로 열어 결과 장면이 바로 보이는지. 데모 CSS 의 `@keyframes`(깜박이는 커서 등)도 `@media (prefers-reduced-motion: reduce)` 에서 멈춘다
2. 접근성: 루트 `<figure role="img" aria-label="무엇을 보여 주는지 한 문장">`. 장면 안 제목은 `h1~h6` 가 아니라 `div`
3. 타입 검사·테스트·운영 빌드(배포 대상 빌드까지, 예: OpenNext·Cloudflare)
4. 추가 용량: 빌드 산출물에서 데모 문구가 든 청크를 찾아 gzip 크기를 적는다
5. dev 서버 주소를 `open <url>` 로 띄워 보여 준다(샌드박스에서 막히면 `! open <url>` 를 넘긴다)
