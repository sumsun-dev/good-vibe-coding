닮았지만 쓰임이 다른 디자인 요소 묶음. 묶음마다 **고르는 기준 → 만드는 법(네이티브 우선) → 흔한 실수**.

## 1. 고르기·입력

| 요소          | 고르는 기준                                                   | 만드는 법                                  |
| ------------- | ------------------------------------------------------------- | ------------------------------------------ |
| 토글(스위치)  | **누르는 순간 반영.** 설정 하나 켜고 끄기                     | `<button role="switch" aria-checked>`      |
| 체크박스      | **저장·제출을 눌러야 반영.** 여러 개 고르기, 약관 동의        | `<input type="checkbox">` + `<label>`      |
| 라디오        | 여럿 중 **하나만**, 선택지 5개 이하로 다 보여야 할 때         | `<fieldset>` + `<input type="radio" name>` |
| 세그먼트      | 하나만 고르되 **보기 전환**(목록/지도, 주/월)처럼 즉시 바뀜   | 라디오 묶음에 버튼 모양 CSS                |
| 셀렉트        | 고른 **값이 칸에 남는다.** 선택지 6개 이상(지역, 은행)        | `<select>` (모바일은 OS 선택기가 뜸)       |
| 드롭다운 메뉴 | 고르면 **바로 실행**되고 값은 안 남음(정렬 실행, 내보내기)    | 버튼 + `popover` 메뉴                      |
| 라벨          | 칸 위에 **남는 글자.** 칸의 이름                              | `<label for>`                              |
| 플레이스홀더  | 칸 안에서 **치면 사라지는 글자.** 예시(“예: 010-1234-5678”)만 | `placeholder` — 이름 대신 쓰지 않는다      |

흔한 실수

- 토글 옆에 저장 버튼 — 즉시 반영인지 모른다. 즉시면 저장 버튼 빼기, 저장해야 반영이면 체크박스 · 검사 `토글+저장 버튼`
- 토글 저장이 서버에서 실패 — 스위치를 되돌리고 옆에 실패를 알린다
- 라벨 없이 플레이스홀더만 — 치는 순간 무슨 칸인지 잊는다 · 검사 `플레이스홀더만`
- 이름 없는 토글·칸 · 검사 `이름 없음`

## 2. 띄우는 창

| 요소     | 고르는 기준                                                             | 만드는 법                                                        |
| -------- | ----------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 모달     | 가운데, **답할 때까지 뒤를 막는다.** 짧은 확인·되돌릴 수 없는 결정      | `<dialog>` + `showModal()` (포커스 가두기·Esc·뒤 막기 기본)      |
| 바텀시트 | 아래에서 올라옴. **모바일에서 선택지·필터·짧은 입력.** 엄지가 닿는 자리 | 아래에 붙인 `<dialog>`, 잡이·스와이프 닫기는 덤 (닫기 버튼 필수) |
| 팝오버   | 누른 요소 **옆에 붙고** 뒤를 막지 않음. 메뉴·짧은 설정                  | `popover` + `popovertarget` (바깥 클릭·Esc 닫힘 기본)            |
| 툴팁     | 올리거나 포커스할 때 **글자만.** 안에 버튼·링크가 있으면 팝오버         | `aria-describedby`, 호버와 포커스 둘 다                          |
| 팝업     | 사용자가 부르지 않았는데 **화면을 가리는 창**(광고·공지)                | 되도록 배너로. 꼭 쓰면 닫기 버튼을 크게, 한 번만                 |

흔한 실수

- `<div class="modal">` 로 직접 만들어 Esc·포커스가 안 됨 · 검사 `가짜 모달`
- 모바일에서 입력칸 여러 개를 가운데 모달에 — 자판에 가려짐. 바텀시트나 새 화면 · 검사 `모바일 가운데 모달`
- 모달 위에 모달 — 두 번째는 같은 창 안 단계나 새 화면
- 제목 없는 창 · 검사 `이름 없음`

## 3. 알림·피드백 — 얼마나 멈춰 세우는가 순

| 요소          | 멈춤 | 고르는 기준                                                     | 만드는 법                                           |
| ------------- | ---- | --------------------------------------------------------------- | --------------------------------------------------- |
| 인라인 메시지 | 0    | **그 칸·그 자리**의 오류·안내. 입력 오류는 무조건 여기          | 칸 아래 글자 + `aria-describedby`                   |
| 배지(점·숫자) | 0    | 새 것이 **있다는 표시**만. 탭·아이콘 위                         | 숫자는 글자로도(`aria-label="새 알림 3개"`)         |
| 토스트        | 0    | 결과만 알리고 **스스로 사라짐**(2–4초). 버튼 없음. "복사했어요" | `role="status"` 영역에 글자 넣기                    |
| 스낵바        | 1    | 토스트 + **행동 하나**(되돌리기·다시 시도). 누를 시간 필요      | `role="status"`, 호버·포커스 때 멈춤                |
| 배너          | 1    | **닫을 때까지 남는** 상태. 오프라인, 결제 실패, 점검            | 화면 위 띠 + 닫기                                   |
| 알림 대화상자 | 2    | **꼭 멈춰서 답해야** 할 때만. 삭제·결제                         | `<dialog>` + `role="alertdialog"`, 버튼 이름은 동사 |

흔한 실수

- 토스트에 버튼 — 그건 스낵바. 사라지는 시간을 늘리고 호버·포커스 때 멈추게 · 검사 `토스트에 버튼`
- 화면 읽기 프로그램이 못 읽는 토스트 — 알림 영역이 처음부터 페이지에 있어야 한다 · 검사 `알림 영역 없음`
- 되돌릴 수 있는 삭제를 대화상자로 확인 — 바로 지우고 스낵바 "되돌리기"
- 오류를 토스트로 — 사라지면 다시 못 본다. 칸 옆이나 배너

## 4. 로딩 — 기다리는 시간으로 고른다

| 기다림       | 요소                                | 고르는 기준·만드는 법                                               |
| ------------ | ----------------------------------- | ------------------------------------------------------------------- |
| 거의 0       | 낙관적 반영                         | 좋아요·체크처럼 거의 성공하는 것은 **먼저 바꾸고** 실패하면 되돌림  |
| 1초 안       | 아무것도 안 띄움                    | 깜빡이는 스피너가 더 느려 보인다. 300ms 뒤에만 띄우기               |
| 1–3초        | 버튼 안 로딩 · 스피너               | 누른 버튼 안에서 돌리고 다시 못 누르게(`aria-busy`, `disabled`)     |
| 1–3초 (화면) | 스켈레톤                            | 실제 레이아웃 크기의 회색 틀. 들어올 모양을 미리 보여 줌            |
| 그림         | 흐린 미리 보기(프로그레시브 이미지) | 작은 흐린 그림 → 원본. `width`·`height` 고정으로 밀림 방지          |
| 3초 넘음     | 진행 막대                           | 남은 양을 알면 `<progress value max>` + 퍼센트, 모르면 `value` 빼기 |
| 10초 넘음    | 진행 막대 + 취소 + 단계 글자        | "사진 올리는 중 2/5". 다른 일을 해도 되면 백그라운드 + 끝나면 알림  |
| 새로고침     | 당겨서 새로고침                     | 목록 맨 위에서만. 웹이면 새로고침 버튼도 함께                       |
| 목록 끝      | 무한 스크롤 로딩 · 더보기 버튼      | 6번 무한 스크롤 참고                                                |
| 앱 시작      | 스플래시                            | 로고만 짧게. 기다림을 숨기는 용도로 늘리지 않는다                   |

흔한 실수

- 화면마다 "로딩" 이라고만 해서 전부 스피너 — 기다림 길이로 고른다
- 스켈레톤 크기가 실제와 달라 들어올 때 화면이 튐
- 이름 없는 진행 막대 · 검사 `이름 없음`

## 5. 막대

| 요소           | 고르는 기준                                                              | 만드는 법                                                      |
| -------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------- |
| 스토리 바      | 위쪽 **조각 막대**, 조각마다 자동으로 넘어감                             | 조각 수만큼 막대, 누르고 있으면 멈춤 · 이전·다음 필수          |
| 스크롤 진행 바 | **긴 글**에서 얼마나 읽었는지. 짧은 화면엔 소음                          | `animation-timeline: scroll()` CSS, 장식이면 `aria-hidden`     |
| 강도 표시기    | 새 비밀번호 칠 때 칸이 차오름. **색만으로 말하지 않는다**                | `<meter>` + "약함/보통/강함" 글자                              |
| 홈 인디케이터  | 아이폰 맨 아래 가로 막대. **OS 것이라 그리지 않는다.** 자리를 비워 둘 뿐 | 아래 고정 요소에 `padding-bottom: env(safe-area-inset-bottom)` |

흔한 실수: 짧은 페이지에 스크롤 진행 바 · 검사 `짧은 화면 스크롤 바` / 강도를 색으로만 · 검사 `강도 색만` / `viewport-fit=cover` 인데 아래 버튼이 홈 인디케이터에 가림 · 검사 `아래 고정 safe-area 없음`

## 6. 이동

| 요소               | 고르는 기준                                                                    | 만드는 법                                                   |
| ------------------ | ------------------------------------------------------------------------------ | ----------------------------------------------------------- |
| 하단 탭바          | **최상위 화면 3–5개**를 자주 오갈 때(홈·검색·내 정보). 모바일 기본             | `<nav>` + 아이콘과 글자 함께, 현재 탭 `aria-current="page"` |
| 앱 바              | 화면 **위 제목 줄.** 뒤로 가기·제목·행동 1–2개                                 | `<header>`                                                  |
| 드로어             | 옆에서 나오는 메뉴. **자주 안 가는 곳이 5개 넘을 때.** 주 메뉴로는 숨김이 심함 | `<dialog>` 옆에 붙이기, 햄버거 버튼으로 열기                |
| FAB(떠 있는 버튼)  | 화면의 **주 행동 딱 하나**(글쓰기, 새 일정). 화면당 하나                       | 오른쪽 아래 고정 + 이름(`aria-label`) + safe-area           |
| 아이콘 버튼        | 작은 **보조 행동**(좋아요, 닫기)                                               | `<button aria-label>`, 누르는 칸 44px 이상                  |
| 뒤로 가기          | 이전 화면으로. **브라우저 뒤로와 같게** 동작해야 함                            | `history` 와 맞추기, 앱 바 왼쪽                             |
| 버튼 vs 링크       | **실행이면 버튼, 이동이면 링크**                                               | 실행 `<button>`, 이동 `<a href>`                            |
| 무한 스크롤        | 끝없이 훑는 피드(SNS). **찾아가야 하는 목록·푸터가 있는 화면엔 안 맞음**       | 끝 감지 `IntersectionObserver` + 로딩 글자, 위치 기억       |
| 더보기·페이지 번호 | 찾기·비교하는 목록(검색 결과, 상품). 푸터에 닿아야 할 때                       | "더보기" 버튼이나 `?page=` 주소                             |

메뉴 아이콘

| 아이콘    | 모양            | 여는 것                                                     |
| --------- | --------------- | ----------------------------------------------------------- |
| 햄버거    | 줄 세 개        | 드로어(전체 메뉴)                                           |
| 케밥      | 세로 점 세 개   | **그 항목**의 더보기(수정·삭제·신고) — 실무 기본            |
| 미트볼    | 가로 점 세 개   | 카드·줄 끝의 더보기 (케밥과 같은 일, 한 앱에선 하나로 통일) |
| 와플·벤토 | 점·네모 아홉 개 | 다른 앱·서비스로 전환                                       |

흔한 실수

- `<a>` 에 `href` 없이 클릭 처리, `href="#"` — 실행이면 버튼으로 · 검사 `링크 모양 버튼`
- 아이콘만 있고 이름 없는 버튼 · 검사 `이름 없음`
- 하단 탭바 6개 이상 — 4–5개로 줄이고 나머지는 "더보기" 탭
- 한 화면에 FAB 와 하단 고정 주 버튼이 함께

## 7. 보여 주기

| 요소                   | 고르는 기준                                                                   |
| ---------------------- | ----------------------------------------------------------------------------- |
| 카드                   | **칸으로.** 그림이 중심이고 하나씩 훑을 때(상품, 장소). 칸 전체가 하나의 링크 |
| 리스트                 | **줄로.** 글이 중심이고 빠르게 비교·훑을 때(설정, 메일, 거래 내역)            |
| 아바타                 | **사람.** 둥근 모양, 그림 없으면 이름 첫 글자                                 |
| 썸네일                 | **콘텐츠.** 네모, 비율 고정(`aspect-ratio`), `alt` 는 내용 설명               |
| 빈 화면: 첫 사용       | 아직 아무것도 없을 때. 무엇이 생기는 곳인지 + **첫 행동 버튼 하나**           |
| 빈 화면: 결과 없음     | 검색·필터 결과 0. 검색어를 보여 주고 **바꿀 방법 하나**(필터 해제, 다른 말)   |
| 빈 화면: 비운 직후     | 다 지웠을 때. 짧게 확인 + **다음 갈 곳**(“둘러보기”)                          |
| 빈 화면: 오류·오프라인 | 무엇이 안 됐는지 + **다시 시도**                                              |

흔한 실수: 빈 화면에 "데이터가 없습니다" 만 — 다음에 누를 것 하나를 꼭 준다 / 카드 안에 링크가 여러 개라 어디를 눌러야 할지 모름

## 12. 디자인 스타일 — "예쁘게" 대신 이름으로

| 스타일        | 생김                                       | 어울리는 곳                       | 대가·주의                                             | CSS 핵심                                                   |
| ------------- | ------------------------------------------ | --------------------------------- | ----------------------------------------------------- | ---------------------------------------------------------- |
| 플랫          | 그림자 없이 면과 색                        | 정보가 많은 앱, 대시보드          | 누를 수 있는지 구분이 약함 → 버튼 모양 분명히         | 단색 배경, 테두리 대신 간격                                |
| 머티리얼(층)  | 옅은 그림자로 **높이**를 표현              | 안드로이드 느낌, 카드형 화면      | 그림자 단계 2–3개로 제한                              | `box-shadow` 단계 토큰                                     |
| 스큐어모피즘  | **진짜 물건처럼**(종이, 가죽, 다이얼)      | 노트·음악·게임, 감성 브랜드       | 무겁고 유행을 탐                                      | 질감 이미지, 그러데이션, 안쪽 그림자                       |
| 뉴모피즘      | 바탕에서 **튀어나온 듯한** 같은 색 덩어리  | 소수의 장식 위젯                  | 대비가 낮아 **버튼·글자에 쓰면 안 보임**              | 같은 색 바탕 + 밝고 어두운 그림자 두 개                    |
| 글래스모피즘  | **뒤가 살짝 비치는** 흐린 유리             | 사진·그러데이션 배경 위 카드      | 뒤 배경에 따라 글자가 안 읽힘 → 대비 4.5:1 확인       | `backdrop-filter: blur()` + 반투명 배경 + 미지원 대비 단색 |
| 리퀴드 글래스 | 애플의 **물방울 유리**. 굴절·반사가 움직임 | 애플 기기 느낌, 떠 있는 탭바·버튼 | 웹에선 근사치만 가능, 무거움. 투명도 줄이기 설정 존중 | 글래스 + 가장자리 하이라이트 + 굴절은 SVG 필터(선택)       |
| 클레이모피즘  | 말랑한 **점토** 같은 둥근 3D               | 어린이·캐주얼 서비스              | 정보 밀도 낮음                                        | 큰 `border-radius` + 안쪽·바깥 그림자                      |
| 브루탈리즘    | 굵은 테두리, 날 것의 글자, 원색            | 포트폴리오, 개성 강한 랜딩        | 업무용 앱엔 피곤함                                    | 검은 2–3px 테두리, 그림자 오프셋                           |
| 미니멀        | 요소를 덜고 **여백과 글자**로              | 대부분의 서비스 기본              | 밋밋함 → 글자 단계와 강조색 하나로 위계               | 넓은 간격, 색 1–2개                                        |

적용 규칙: 한 화면엔 스타일 하나. 프로젝트 토큰(색·간격·둥글기)을 스타일에 맞게 바꾸되 브랜드 색은 유지. 반투명·저대비 스타일은 적용 후 대비를 잰다. `prefers-reduced-transparency` 가 있으면 단색으로.

## 14. 버튼 위계 — 한 화면에서 무엇을 먼저 누를지

| 요소       | 고르는 기준                                                           | 만드는 법                              |
| ---------- | --------------------------------------------------------------------- | -------------------------------------- |
| 주(Filled) | 흐름을 끝내는 **가장 중요한 행동** 하나(저장·가입). HIG: 화면당 1–2개 | 강조색 배경, 동사 이름                 |
| 톤         | 주와 보조 사이. 온보딩 "다음"                                         | 옅은 강조색 배경                       |
| 보조       | 중요하지만 주는 아닌 것                                               | 테두리 + 투명 배경                     |
| 텍스트     | **가장 낮은 우선순위**(취소·건너뛰기)                                 | 글자만, 누르는 칸은 유지               |
| 고스트     | 사진·그러데이션 위 외곽선 버튼 (1차 출처 정의 미확인)                 | 외곽선 대비 확인                       |
| 위험       | 되돌리기 **어려운** 삭제·탈퇴. 되돌릴 수 있으면 스낵바 되돌리기(3번)  | 빨강 + 결과를 말하는 글자("계정 삭제") |

흔한 실수

- 주 버튼 3개 이상 — 위계가 사라진다
- 위험 버튼을 주 버튼 자리·모양으로, 또는 무해한 버튼 바로 옆에 — 안전한 쪽을 주로, 간격을 띄운다 · 검사 `위험 버튼 자동 포커스`
- 나란한 버튼을 크기로 구분 — 같은 크기, 스타일로만
- 제출 버튼을 처음부터 `disabled` — 왜 안 눌리는지 모른다. 눌렀을 때 오류를 알린다 · 검사 `미리 막힌 제출`
- 누르는 칸이 24×24px 미만 (WCAG 2.5.8 AA, 문장 속 링크는 예외) · 검사 `작은 누르는 칸`

## 15. 입력 컨트롤 — 값의 성격으로 고른다

| 요소            | 고르는 기준                                                 | 만드는 법                                                                                               |
| --------------- | ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 슬라이더        | **대략**이면 되는 값(가격대, 볼륨). 정확한 값엔 쓰지 않는다 | `<input type="range">` + `<output>` 으로 값 표시, 트랙을 눌러도 고를 수 있게                            |
| 스테퍼          | 작은 정수를 ±1씩(수량)                                      | − / 숫자칸 / + 버튼, 칸은 `inputmode="numeric"`                                                         |
| 숫자칸          | 전화·카드·우편번호처럼 **세지 않는 숫자**                   | `type="text" inputmode="numeric"` (`type="number"` 아님, GOV.UK)                                        |
| 날짜: 달력      | 1년 안의 가까운 날짜(예약)                                  | `<input type="date">`, 직접 입력도 허용                                                                 |
| 날짜: 직접 입력 | 먼 날짜(생일)                                               | 년·월·일 칸 + `autocomplete="bday-year"` 등                                                             |
| 칩: 필터        | 목록 거르기                                                 | `<button aria-pressed>` 또는 체크박스 묶음                                                              |
| 칩: 입력        | 넣은 값 조각(받는 사람)                                     | 칩 + 지우기 버튼(`aria-label="홍길동 지우기"`)                                                          |
| 검색 자동완성   | 치는 대로 후보                                              | 단순하면 `<input list>` + `<datalist>`, 직접 만들면 `role="combobox"` + `aria-expanded`·`aria-controls` |
| OTP             | 문자로 받은 일회용 코드                                     | **칸 하나** `autocomplete="one-time-code" inputmode="numeric"`, 나눈 모양은 CSS로                       |

흔한 실수

- 슬라이더에 값 표시가 없음 · 검사 `슬라이더 값 안 보임`
- 전화·카드번호를 `type="number"` 로 · 검사 `숫자 아닌 숫자칸`
- OTP 를 `maxlength=1` 칸 6개로 — 자동 채우기·붙여넣기가 깨진다 · 검사 `칸 나눈 OTP`
- 생일을 달력으로 — 수십 년을 넘겨야 한다 · 검사 `생일 달력`
- 직접 만든 자동완성에 상태 없음 · 검사 `콤보박스 상태 없음`

## 16. 폼 흐름 — 나누는 법과 오류를 알리는 때

| 요소            | 고르는 기준                                                            | 만드는 법                                                            |
| --------------- | ---------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 한 화면 한 질문 | 처음 하는 일, 모바일, 답에 따라 다음 질문이 갈릴 때 (GOV.UK 기본)      | 질문을 그 화면의 `<h1>` 로                                           |
| 묶은 짧은 폼    | 서로 붙은 질문(주소 한 벌), 자주 하는 일                               | `<fieldset>` + `<legend>`                                            |
| 단계 표시기     | 3단계 이상 마법사                                                      | `<ol>` + 현재 항목 `aria-current="step"`                             |
| 이전·다음       | "다음" 대신 **갈 단계 이름**("배송지로")                               | 이전은 입력값 유지                                                   |
| 칸 오류         | 칸을 **떠날 때** 검사. 치는 도중엔 띄우지 않는다(비밀번호 강도는 예외) | 칸 아래 글자 + `aria-describedby`, `aria-invalid="true"`             |
| 오류 요약       | 제출 뒤 오류가 여럿일 때                                               | 맨 위에 칸으로 가는 링크 목록 + 포커스 이동 + `<title>` 앞에 "오류:" |
| 중간 저장       | 길고 중요한 흐름                                                       | 나갔다 와도 이어서                                                   |

흔한 실수

- 첫 글자를 치자마자 빨간 오류 (눈으로 확인: 빈 칸에 한 글자 치고 blur 전에 오류가 뜨는지)
- 오류 요약만 있고 칸 옆 글자가 없음, 또는 칸과 오류 글자가 연결 안 됨 · 검사 `오류 연결 없음`
- 앞 단계에서 넣은 값을 다시 물음 (WCAG 3.3.7 A)
- 단계 표시에 현재 단계 표시 없음 · 검사 `단계 현재 표시 없음`

## 17. 온보딩 — 되도록 안 하고, 하면 그 자리에서

| 요소           | 고르는 기준                                                         | 만드는 법                                    |
| -------------- | ------------------------------------------------------------------- | -------------------------------------------- |
| 첫 실행 캐러셀 | NN/g 는 **권하지 않는다.** 꼭 쓰면 카드 적게, 카드당 개념 하나      | `scroll-snap-type` + 점 표시 + 큰 "건너뛰기" |
| 코치마크       | 처음 보는 **독특한 기능 하나**, 그 화면에 처음 왔을 때 한 번에 하나 | 대상 옆 `popover` + 닫기                     |
| 투어           | 거의 안 맞는다. 쓰면 "1/3" + 끝내기                                 |                                              |
| 해 보는 안내   | 새 흐름을 안전하게 연습                                             | 실제 화면 + 연습용 데이터                    |
| 맥락 팁        | 그 일을 할 때 그 자리에서 짧게 (HIG 권장)                           | 인라인 안내 글이나 팝오버                    |
| 점진적 공개    | 기능이 많은데 대부분 몇 개만 쓸 때. 2단계까지                       | `<details>` + `<summary>`                    |

흔한 실수

- 앱을 열자마자 기능 소개 카드 — 직접 해 보게 하고 설정은 미룬다
- 건너뛴 튜토리얼을 다음에 또 띄움 — 도움말에서 다시 볼 곳만 남긴다
- 건너뛰기·닫기가 없음 · 검사 `건너뛰기 없음`
- 코치마크 여러 개를 동시에 · 검사 `연속 코치마크`
- 5초 넘게 스스로 넘어가는데 멈춤이 없음 (WCAG 2.2.2 A)

## 18. 오류·권한 — 막다른 길을 만들지 않는다

| 요소           | 고르는 기준                                                     | 만드는 법                                                                       |
| -------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 권한 요청 시점 | 그 기능을 **처음 쓸 때.** 시작할 때는 그것 없이 안 돌 때만(HIG) | 버튼 `click` 안에서 `Notification.requestPermission()` 등                       |
| 사전 설명 화면 | 맥락만으로 이유가 안 보일 때만                                  | 이유 한 줄 + 버튼 **하나** "계속". "허용" 이라 쓰지 않는다(HIG)                 |
| 거부된 뒤      | 다시 물을 수 없을 때가 많다                                     | 기능 자리에 설명 + 설정 여는 방법, `navigator.permissions.query()` 로 상태 확인 |
| 404            | 없는 주소                                                       | 실제 HTTP 404 + "페이지를 찾을 수 없어요" + 홈·검색·주요 링크                   |
| 서버 오류(5xx) | 우리 탓                                                         | 사과 + 다시 시도 + 입력값 유지                                                  |
| 오프라인       | 연결 끊김                                                       | 배너(3번) + 다시 시도. `navigator.onLine` 은 힌트로만                           |
| 권한 없음(403) | 로그인은 했는데 못 보는 곳                                      | 누구에게 권한을 받는지 + 돌아갈 곳                                              |

흔한 실수

- 페이지를 열자마자 알림·위치 권한 (눈으로 확인: 새로 열고 아무것도 안 눌렀는데 권한 창이 뜨는지)
- 사전 설명 화면에 "허용" 버튼 — 시스템 창 흉내 · 검사 `사전 화면 허용 버튼`
- 404 에 "Not Found" 만, 갈 곳 없음 · 검사 `404 막다른 길`
- 오류가 나면 입력값을 비움

## 19. 표·데이터 — 찾기·비교·일괄 처리

| 요소        | 고르는 기준                                        | 만드는 법                                                                  |
| ----------- | -------------------------------------------------- | -------------------------------------------------------------------------- |
| 표          | 여러 열을 **비교**할 때. 열 2개 이하면 리스트(7번) | `<table>` + `<caption>` + `<th scope="col">`                               |
| 첫 열       | 사람이 읽는 식별자(이름·주문번호)                  | `<th scope="row">`                                                         |
| 정렬        | 열 기준 줄 세우기                                  | `th` 안 `<button>`, 정렬된 열 **하나에만** `aria-sort`                     |
| 필터 칩     | 자주 쓰는 조건을 바로. 걸린 필터는 늘 보인다       | 표 위 칩 줄 + "모두 지우기"                                                |
| 고정 머리줄 | 표가 화면보다 클 때                                | `thead th { position: sticky; top: 0 }` + **불투명 배경**                  |
| 일괄 선택   | 같은 일을 여러 줄에                                | 줄마다 체크박스 + 전체 선택(`indeterminate`) + "3개 선택됨 · 삭제"         |
| 숫자 열     | 금액·수량                                          | 오른쪽 정렬 + `font-variant-numeric: tabular-nums` (관례, 1차 출처 미확인) |
| 좁은 화면   | 열이 많을 때                                       | `overflow-x: auto` 감싸개 + 고정 첫 열, 또는 줄을 카드로                   |

흔한 실수

- 이름 없는 표 · 검사 `표 이름 없음`
- 정렬 상태를 화살표 그림으로만, 또는 여러 열에 `aria-sort` · 검사 `정렬 표시 겹침`
- 고정 머리줄 배경이 투명해 아래 줄과 겹침 · 검사 `고정 머리 투명`
- 걸린 필터·선택 개수가 안 보임

## 20. 모션 이름 — "부드럽게" 대신 이름과 값으로

| 이름           | 언제                                                             | 값·만드는 법                                                                                                   |
| -------------- | ---------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| ease-out       | **들어올 때.** 빨리 시작해 천천히 멈춤                           | M3 emphasized-decelerate `cubic-bezier(0.05, 0.7, 0.1, 1)`                                                     |
| ease-in        | **나갈 때.** 짧게                                                | M3 emphasized-accelerate `cubic-bezier(0.3, 0, 0.8, 0.15)`                                                     |
| standard       | 화면 안에서 자리만 옮길 때                                       | M3 standard `cubic-bezier(0.2, 0, 0, 1)`                                                                       |
| linear         | 진행 막대·스피너처럼 일정한 것만                                 | `linear`                                                                                                       |
| 길이           | 작은 피드백 약 100ms, 큰 변화 200–300ms, 나갈 때가 더 짧게(NN/g) | M3 토큰 short2 100ms · short4 200ms · medium2 300ms · medium4 400ms                                            |
| spring         | 끌어 놓기, 튕기듯 멈추기                                         | CSS `linear()` 근사나 JS (M3 Expressive spring 값 미확인)                                                      |
| stagger        | 목록 항목이 차례로 들어옴. **첫 등장에만**                       | `animation-delay: calc(var(--i) * 간격)` (권장 간격 미확인)                                                    |
| 공유 요소 전환 | 썸네일이 상세 그림으로 커짐                                      | `document.startViewTransition()` + 같은 `view-transition-name`, MPA 는 `@view-transition { navigation: auto }` |
| 스크롤 연동    | 읽은 만큼 차오르기, 나타나기                                     | `animation-timeline: scroll()` / `view()`                                                                      |

흔한 실수

- 모든 곳에 같은 `ease` 300ms — 들어올 때·나갈 때를 나누고 크기만큼만
- `transition: all` — 레이아웃까지 움직여 버벅인다. `transform`·`opacity` 만 · 검사 `전부 움직임`
- 다시 그려질 때마다 stagger
- 같은 `view-transition-name` 이 둘 — 전환이 건너뛰어진다 · 검사 `전환 이름 겹침`

## 21. 이동 보조 — 지금 어디 있는지

| 요소           | 고르는 기준                                                          | 만드는 법                                                                           |
| -------------- | -------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| 브레드크럼     | 3단계 넘는 **계층**(쇼핑 분류, 문서). 방문 기록 아님                 | `<nav aria-label="현재 위치"><ol>`, 마지막은 링크 아닌 글자 + `aria-current="page"` |
| 탭             | 한 화면 안 **묶인 긴 내용** 전환. 비교할 내용이면 한 페이지에 소제목 | `role="tablist"`/`tab`/`tabpanel`, `aria-selected`, 화살표 키. 한 줄, 1–2단어       |
| 아코디언       | 모바일, 짧은 내용(FAQ)                                               | `<details name="같은이름">` (하나만 열기)                                           |
| 세그먼트       | 같은 데이터의 보기 전환 (1번). 탭은 내용이 다른 패널                 |                                                                                     |
| 스티키 헤더    | 자주 쓰는 것(검색·장바구니)이 있을 때만                              | `position: sticky; top: 0`, 불투명 배경, 낮게 + `html { scroll-padding-top }`       |
| 반쯤 고정 헤더 | 내릴 땐 숨고 **올리면 나타남**                                       | 조금만 올려도 300–400ms 로 내려옴(NN/g)                                             |
| 맨 위로        | 아주 긴 목록                                                         | 오른쪽 아래, FAB 와 겹치지 않게                                                     |

흔한 실수

- 브레드크럼 마지막이 자기 자신 링크 · 검사 `브레드크럼 현재 링크`
- 탭이 두 줄로 쌓이거나, 선택된 탭이 0개·여러 개 · 검사 `탭 선택 오류`
- 스티키 헤더가 Tab 포커스를 가림 (WCAG 2.4.11 AA) — `scroll-padding-top` 으로 · 검사 `고정 헤더 scroll-padding 없음`
- 반투명 헤더라 아래 글자와 겹쳐 읽힘
