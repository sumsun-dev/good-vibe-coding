# Working Style

사용자에게 일을 넘기는 순간에 생기는 왕복과 사고를 줄이는 규칙.

## 1. 검증은 끝까지 직접

- 브라우저 테스트, `curl`·서버 로그 확인, 만든 테스트 데이터 정리까지 Claude 가 하고 결과는 표로 보고한다. 체크리스트만 넘기지 않는다
- 사용자에게 넘기는 건 할 수 없거나 해선 안 되는 것만: 2단계 인증·로그인, 비밀값 입력·복사, 토큰 생성 같은 최종 버튼. 그 직전까지는 채워 둔다

## 2. 비밀값은 `!` 가 아니라 터미널 앱에서

- `!` 로 실행한 명령은 입력창(TTY)을 띄우지 못해, `wrangler secret put`·`gh auth login`·`vercel env add` 같은 프롬프트가 **빈 값으로 저장**될 수 있다
- 비밀값 입력은 처음부터 "별도 터미널 앱에서 `cd <repo> && <명령>`" 으로 안내한다
- 넣은 뒤엔 실제 동작(로그인, 예약 작업 결과)이나 서버 로그로 들어갔는지 확인한다
- 실제 사례: `! npx wrangler secret put ADMIN_PASSWORD` → 빈 값 저장 → 운영 로그인 500

## 3. auto mode 에서 막히는 단계는 `!` 한 줄로

- auto mode 의 권한 분류기는 리뷰 없는 PR 머지, 운영 배포, `git push --force*`, 원격 태그 푸시·브랜치 삭제를 거부한다. 직접 시도하지 않는다
- 그 전 단계(테스트·빌드·PR·로컬 검증)까지 끝낸 뒤 한 줄로 묶어 준다:
  ```
  ! cd <repo> && gh pr merge <N> --squash --delete-branch && git checkout <main> && git pull && <배포 명령>
  ```
- 강제 푸시가 필요하면 새 브랜치 + 새 PR 로 우회한다
- 분류기 거부를 풀어 주는 권한 규칙은 제안하지 않는다 (안전장치)
